# 参与 Skill 环节索引

本文件是路由时查阅的环节目录。每个环节的完整契约（调度条件、所需输入、专项产出、完成条件）以各参与 Skill 自身 SKILL.md 的"调度接口"一节为单一事实源；本索引只列环节名与调度时机。索引与各 Skill 文件不一致时，以各 Skill 文件为准，并在此记录差异。

## skill-creator（核心硬门禁）

| 环节 | 调度时机 |
|---|---|
| 创建与起草 | 候选方案定型后生成正式 Skill；instruction-only 候选直接走此环节 |
| 结构校验与安装 | 候选写入正式位置前后；改造既有 Skill 的正式更新 |
| 打包分发 | 用户明确要求导出、分享或跨工作区分发时 |

## skill-effectiveness-evaluator（核心硬门禁）

| 环节 | 调度时机 |
|---|---|
| 快速探索 | 首次判断、低风险筛选、发现方向；默认层级 |
| 标准比较 | 多版本选择、优化决策、需要人工复核 |
| 严格审计 | 版本归档、重要决策、对外或高风险使用 |

调度的必填输入：候选位置、任务卡中的验收标准草案（原样）。标准比较与严格审计仅在 skill-orchestrator 编排流程中接受调度。

## writing-for-agents（条件调度专项）

| 环节 | 调度时机 |
|---|---|
| 结构审查 | 候选存在触发、流程分支、指令层级、引用指针、上下文成本或完成条件风险时；或既有 Skill 的改造涉及上述方面 |

不以"润色措辞"为目的调度；产出必须是可定位的结构建议及对应问题。

## skill-from-externals（条件调度专项）

| 环节 | 调度时机 |
|---|---|
| 分支 A 现成复用 | 需要判断已有能力能否复用时；先查团队工作区，再查外部生态 |
| 分支 B 机制学习 | 标杆侦察发现可靠 GitHub 项目且其机制能改变本轮设计时 |

两个分支的产出均须包含来源归属与不可直接迁移部分。

## skill-from-masters（条件调度专项）

| 环节 | 调度时机 |
|---|---|
| 实践案例学习 | 标杆侦察发现足够具体的黄金/失败/对照案例，且案例规律能改变本轮行为规则时 |

产出的有效/无效对照须标注案例证据分级（一手细节 > 转述 > 理论归纳）。
