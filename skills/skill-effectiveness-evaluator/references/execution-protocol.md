# 独立子代理执行协议

## 全局硬门禁

所有实验任务执行角色和所有盲审角色必须是独立子代理。主协调 Agent 只能负责对齐、预注册、派发、证据核验、汇总和交付，不得亲自生成候选执行产物或盲审评分。

每个任务、每个候选、每次重试和每轮盲审都必须通过 `task` 工具创建新的子代理，并使用 `context: "fresh"`。不得用主 Agent 当前上下文、同一子代理的连续对话或仅切换目录替代独立子代理。

## 任务执行派发

标准调用约束：

```text
task(
  subagent_type="general",
  context="fresh",
  prompt="...只注入本单元允许的输入、候选 Skill 和执行要求..."
)
```

实际可用的 `subagent_type` 由运行环境决定；核心要求是 `context: "fresh"` 和独立子代理身份。

派发给任务执行子代理的内容只能包括：

- 当前任务的实际用户输入；
- 允许背景和正式确认消息；
- 分配给该单元的一个候选 Skill 或控制条件；
- 必要的输出格式和保存要求。

不得注入：

- 成功标准、预期判断、事实账本或评分卡；
- 其他候选、其他单元、历史报告、映射或工作区记忆；
- 会诱导执行者绕过确认门槛的指令。

每个子代理单元必须：

1. 使用独立运行目录；
2. 保存完整 `transcript.md`，包括用户输入、完整返回、关键工具调用和 Skill 加载证据；
3. 保存最终 `artifact.md`；
4. 保存 `input.json` 和 `execution.json`；
5. 返回结构化结果，至少包含 `status`、`verification`、`concerns`、`next_steps`、产物路径和约束检查；
6. 只记录执行事实，不宣告实验总结果。

主协调 Agent 必须运行 `python scripts/verify_run_units.py <runs-or-unit>`，并核对：

- 子代理确实由 `task(context: "fresh")` 创建；
- 单元 ID、候选、任务和输入指纹匹配；
- transcript 和 artifact 完整存在；
- Skill 加载、方法注入或控制条件证据可定位；
- 结构化结果完整。

无法证明独立子代理执行、输入一致或关键材料完整时，不能标记 `VALID`。通常标记 `LIMITED`；缺少完整产物或关键证据时标记 `INVALID`。

## 重试

工具失败、超时、并发拒绝或保存失败时，不得把主 Agent 摘要当作产物。重试必须创建新的 fresh 子代理和新的单元 ID；保留旧单元失败记录，并在严格模式记录替代关系。

## 首轮盲审派发

首轮盲审也必须由独立 fresh 子代理完成，不能由主协调 Agent 自己评分：

```text
task(
  subagent_type="general",
  context="fresh",
  prompt="...只注入冻结盲审包、评分卡和盲审规则..."
)
```

盲审子代理只可读取：

- 冻结的匿名盲审包；
- 评分卡；
- 本轮盲审规则；
- 实验设计中预注册且明确允许的统一事实来源包。

禁止读取：

- 首轮报告、既有分数、共识报告；
- `mapping.json`、原始运行目录、输入目录；
- 真实版本名和组别信息；
- 工作区记忆或其他历史材料。

盲审子代理必须：

1. 先阅读同一任务的全部候选，再逐项评分；
2. 每项评分附原文证据或明确指出证据缺失；
3. 分开评价最终质量与过程质量；
4. 返回并保存结构化评分结果、完整盲审记录和状态；
5. 报告置信度、平局、分歧和无法判断项；
6. 不输出候选真实身份或版本推荐。

## 跨模型复评

只有准确模型 ID 与首轮不同，才能称为跨模型复评。复评模型必须再次派发独立 fresh 盲审子代理；子代理只读取上一轮冻结的同一盲审包、评分卡和盲审规则。

复评必须复用：

- 同一盲审材料内容；
- 同一 `CAND-*` 标签；
- 同一 `blind_pack_hash`；
- 同一评分维度和核验模式。

协调者必须核验复评结果的盲审包哈希、标签、评分文件完整性和准确模型 ID。不能选择或核验不同模型时，停止复评并只生成交接卡。

## 结果交付

人工查看材料和匿名盲审材料必须分离。人工查看入口应链接子代理完整 transcript、最终 artifact、execution、status 和盲审记录；匿名包不得包含真实版本、组别、映射或人工查看入口。
