# 严谨模式 2.0（rigor-mode-v2）

**当前版本：2.2.0**（2026-09-14 发布，备注"整体性能优化"）

一套让 AI 在高价值任务中"先答对问题，再答得对"的工作流：开工前对齐目标，过程中选对思考框架，交付时给出依据，并按风险决定是否进行独立审核与反证压测。

> 本目录与 SkillsHub `sug-ur-skills/rigor-mode-v2` 的 2.2.0 发布包逐文件一致（SKILL.md、frameworks.md、principles.md、review-prompt.md）。**发布版本以 SkillsHub 为准**，本目录跟随更新。

## 什么时候触发

仅在用户主动要求时启用，例如"使用 rigor-mode-v2""开启严谨模式""请按严谨模式分析"。AI 不会因为任务复杂或风险高而自行启用。

不适用：闲聊、灵感发散、简单改写、快速草稿、可即时纠正的低成本问答。

## 七个阶段

| 阶段 | 做什么 | 是否需要用户回应 |
|---|---|---|
| ① 任务对齐 | AI 预填任务对齐单（目标、语境、取舍、完成标准、边界） | 必须确认或修正后才继续 |
| ② 思考路由 | 按任务性质选 1 个主框架 + 必要辅助框架，给出不超过 3 步的执行方案 | 仅当方案改变已确认的取舍、成本或边界时 |
| ③ 执行 | 完成任务；事实、推断、工作假设分开，受限时披露降级 | 否 |
| ④ 基础核验 | 完成标准复核、关键事实核验；流程类任务做首次走查；修订并复检 | 否 |
| ⑤ 基础交付与核验选择 | 交付结果，说明做了什么、还有什么未核验，并判断是否建议加强核验 | 建议加强时需选择"加强核验"或"基础交付即可" |
| ⑥ 加强核验 | 独立子 Agent 审核 + 反证与压力测试 + 修订复检，最多 2 轮返修 | 仅在用户选择加强后进行 |
| ⑦ 最终状态确认 | 交付最终版本，重申实际核验强度与遗留风险 | 否 |

各阶段有明确的"通过闸门"，闸门未满足不得进入下一阶段。

## 文件结构

```text
rigor-mode/
├── SKILL.md                  # 完整流程、闸门与交付要求（frontmatter name: rigor-mode-v2）
├── README.md                 # 本说明
└── references/
    ├── frameworks.md         # 14 种认知框架的操作指令库，按需读取
    ├── principles.md         # 各阶段原则与判定依据，说明"为什么这样做"
    └── review-prompt.md      # 派发独立审核子 Agent 时使用的提示词
```

## 安装与使用

- `SKILL.md` 的 frontmatter 名称是 `rigor-mode-v2`。安装到本地技能目录时，建议目录名也用 `rigor-mode-v2`，与名称保持一致；仓库中的目录名 `rigor-mode` 沿用旧链接。
- 需要整套使用时复制整个目录（含 `references/`），只复制 `SKILL.md` 会缺少框架库和审核提示词。
- 加强核验依赖平台的独立子 Agent 能力；不可用时，按 `SKILL.md` 披露"未完成独立审核"并做替代复核。
