# 严谨模式（Rigor Mode）

一套帮助 AI 输出更可靠、更可验证、更经得起推敲的严谨工作流。不靠"请认真一点"这种空泛要求，而是把质量要求拆成可确认、可检查、可修订的标准化步骤。

## 它做什么

把严谨协作固定为四个阶段：

1. **任务对齐**：AI 基于原始输入预填"任务对齐单"，确认目标、使用语境、优先取舍、完成标准、边界与核验强度后才进入实质执行。
2. **执行**：产出实际内容，同时把信息分为"已核实、待核实、工作假设"，并说明判断依据、关键假设、范围与待核验项。
3. **核验与修订**：所有任务完成自检、关键事实核验与核验摘要；流程/计划类任务额外做模拟走查；核验强度为**加强**的任务再增加独立子 agent 冷读与反证压力测试；根据发现修订并复检。
4. **交付**：交付可直接使用的主内容，并附核验摘要、遗留风险和发送/决策前必核项。详细审核记录仅在需要追溯时作为附录提供。

## 什么时候用

适用于需要处理复杂信息、形成重要结论、开展研究分析、进行方案决策或完成关键写作的场景。

不适用于闲聊、灵感发散、简单改写、快速草稿或可低成本纠错的任务。

仅当用户明确输入"走严谨模式"或 use rigor mode 时启用，不自动介入普通任务。

## 关键原则

- **先确认问题，再开始解题。** 对齐单由 AI 预填，不把空表格丢给用户；用户确认是开工门槛。
- **展示依据与限制，不展示冗长逐步推理。** 用户需要验证的是证据、前提、边界和可行动性。
- **不混淆事实状态。** 已核实、待核实和工作假设必须分开；待核实信息和假设不能包装成确定事实。
- **核验强度随任务影响分级。** AI 在任务对齐时建议基础/加强并说明理由，用户确认后执行；对外发布、关键决策、证据链复杂或不可逆后果建议加强。
- **优先核验关键事实。** 发送或决策前优先核金额、日期、条款、引用、涉及个人/组织的事实及会改变关键选择的信息。
- **修订后复检。** 修改可能引入新假设、新依赖或新风险，不能修改完就直接交付。
