# 认知框架操作指令库

每个框架包含：核心问题、操作步骤、适用场景、常见误用。按需读取当前任务所用的框架，不必一次加载全文。

## 1. 奥卡姆剃刀（Occam's Razor）

**核心问题**：在多个解释中，哪个最简单且足够解释事实？

**操作步骤**：

1. 列出主要解释/假设
2. 比较各自引入的额外假设
3. 优先选择假设较少且解释力足够者
4. 只有在简单解释与事实冲突时再增加复杂度

**适用场景**：异常归因、故障排查、指标异动、用户行为解释

**常见误用**：把“简单”当“正确”。它是启发式工具，不是证明工具。

## 2. 第一性原理（First Principles）

**核心问题**：问题背后不可再分解的基本事实是什么？

**操作步骤**：

1. 列出默认假设
2. 区分事实与惯例/经验
3. 拆解到基础需求、物理限制或经济规律
4. 从基础事实重新推导
5. 与常规方案比较差异

**适用场景**：创新、战略重构、产品从零设计

**常见误用**：把“从基本原理推导”变成否定现有方案。

## 3. 五个为什么（5 Whys）

**核心问题**：真正的、可行动的原因是什么？

**操作步骤**：

1. 描述问题现象
2. 连续追问“为什么会发生”
3. 到达可行动的根因后停止
4. 验证：解决根因后问题是否仍会发生

**适用场景**：反复出现的问题、流程故障、根因分析

**常见误用**：机械地问五次。次数不是目的。

## 4. 贝叶斯思维（Bayesian Thinking）

**核心问题**：新证据如何改变不同假设的相对可信度？

**操作步骤**：

1. 列出竞争性假设
2. 评估先验可信度
3. 比较新证据在各假设下的解释力
4. 更新判断并继续迭代

**适用场景**：预测、决策、假设检验、趋势判断、竞品分析

**常见误用**：把它当成必须精确计算概率的工具；实际应用重点是随证据更新判断。

## 5. MECE 原则（Mutually Exclusive, Collectively Exhaustive）

**核心问题**：如何分类才能尽量不重不漏？

**操作步骤**：

1. 列出待分类要素
2. 检查类别边界是否重叠
3. 检查是否存在关键遗漏
4. 调整边界或补类

**适用场景**：报告框架、问题拆解、信息整理、用户分层

**常见误用**：为了 MECE 而 MECE；实用性优先。

## 6. 帕累托法则（Pareto Principle / 80-20 法则）

**核心问题**：哪些少数因素贡献了大部分结果？

**操作步骤**：

1. 列出影响结果的主要因素
2. 评估贡献度
3. 找出关键少数
4. 优先投入资源

**适用场景**：资源分配、时间管理、功能取舍、优先级排序

**常见误用**：把 80/20 当精确比例。

## 7. 逆向思维（Inversion / Munger's Inversion）

**核心问题**：怎样会失败？

**操作步骤**：

1. 明确目标
2. 反转问题：怎样确保失败？
3. 列出失败条件
4. 检查当前方案是否包含这些条件
5. 消除或规避

**适用场景**：风险评估、方案审查、项目启动前检查

**常见误用**：把逆向思维等同于悲观。

## 8. 系统思维（Systems Thinking）

**核心问题**：各要素如何相互影响？系统中有哪些反馈回路？

**操作步骤**：

1. 识别关键要素和利益相关方
2. 建立因果关系
3. 寻找正/负反馈
4. 识别系统陷阱
5. 寻找高杠杆干预点

**适用场景**：组织问题、市场生态、平台竞争、政策评估、复杂系统

**常见误用**：对简单线性问题强行引入系统复杂度。

## 9. 博弈论（Game Theory）

**核心问题**：对方会如何根据我的动作调整策略？

**操作步骤**：

1. 识别参与方、目标和策略
2. 推演关键动作的可能反应
3. 找出稳定策略组合或关键依赖
4. 评估策略是否依赖特定反应

**适用场景**：竞争、谈判、定价、生态合作、市场进入

**常见误用**：把简化模型当精确预测。

## 10. 证伪主义（Falsificationism / Popper）

**核心问题**：什么证据可以推翻这个主张？

**操作步骤**：

1. 明确主张
2. 指定可能推翻它的观察结果
3. 主动寻找反例或证伪证据
4. 区分“尚未被推翻”和“不可证伪”

**适用场景**：观点判断、假说验证、信息甄别、研究结论评估

**常见误用**：把“可证伪”当“已证伪”。

## 11. 红队思维（Red Teaming / Devil's Advocate）

**核心问题**：这个方案哪里最可能崩？

**操作步骤**：

1. 站在最严厉批评者的位置
2. 找出会推翻核心结论的前提
3. 找出最有力的利益相关方反对意见
4. 找出最可能的执行失败点
5. 逐项回应并修订

**适用场景**：方案评审、计划制定、风险排查、重要决策

**常见误用**：为了“找问题”而制造问题。应只报告实质脆弱点。

## 12. TRIZ 矛盾解决（TRIZ Contradiction Resolution）

**核心问题**：既要提升 A，又要避免牺牲 B，怎么办？

**操作步骤**：

1. 明确技术矛盾
2. 映射到通用工程参数
3. 查找推荐创新原理
4. 转化到具体场景
5. 检查是否真正消除矛盾

**适用场景**：工程设计、产品矛盾、资源冲突、性能权衡

**常见误用**：把 TRIZ 当标准答案库。

## 13. SCAMPER 创意法

**核心问题**：有哪些方式可以改变现有方案？

**操作步骤**：

1. Substitute 替代
2. Combine 组合
3. Adapt 改造
4. Modify 修改
5. Put to another use 新用途
6. Eliminate 删除
7. Reverse 反转

**适用场景**：创意脑暴、功能设计、营销玩法、产品改进、流程优化

**常见误用**：把它机械执行成 checklist。

## 14. 二阶思维（Second-Order Thinking）

**核心问题**：这个结果还会带来什么结果？

**操作步骤**：

1. 列出直接结果
2. 追问后续反应
3. 必要时继续到第三阶
4. 比较短期与长期影响

**适用场景**：政策评估、长期战略、技术影响、组织变革、投资决策

**常见误用**：无限推演；通常 2-3 阶已足够。

## 框架冲突处理

不同框架可能揭示不同层面。原则是**先切后验**：

1. 用一个框架形成初步判断
2. 用另一个框架检验关键假设
3. 合并各自贡献的洞察，说明冲突来自哪个层面

## 使用弹性

- **跳过步骤**：只取最有穿透力的动作
- **部分采用**：只用适用步骤
- **不用框架**：没有匹配问题难点时直接分析

## 常见组合模式

| 场景   | 推荐组合            | 分工             |
| ---- | --------------- | -------------- |
| 异常归因 | 奥卡姆剃刀 + 五个为什么   | 先筛选合理解释，再追溯根因  |
| 创新设计 | 第一性原理 + TRIZ    | 先重构问题，再处理具体矛盾  |
| 方案评审 | 逆向思维 + 红队思维     | 先找失败路径，再做压力测试  |
| 战略规划 | 系统思维 + 二阶思维     | 先理解系统，再推演长期影响  |
| 决策选择 | 贝叶斯思维 + 帕累托法则   | 先更新判断，再聚焦关键变量  |
| 创意生成 | SCAMPER + 第一性原理 | 先抓住本质需求，再发散方案  |
| 观点判断 | 证伪主义 + 贝叶斯思维    | 先检验可证伪性，再更新可信度 |
