# 图解报告（graphic-report）

把杂乱内容变成**读者一眼能看懂关系**的 HTML 页面或宿主页面中的图形片段。核心不是"配图"，而是**先弄清内容里有什么关系，再用最贴切的图把它讲清楚**。

## 一、工作原则（先读）

1. **启用本技能，就意味着用户希望尽量图形化。** 默认先判断内容能否清晰、忠实地图解；**适合图解就必须画**，只有难以用图示说清楚时才用文字或表格承接。不要再把"纯文字是否已经够清楚"作为是否画图的前置门槛。
   - 图形化不只是数据图表：分组、层级、对照、路径、状态、位置、数字层级和视觉强调都属于图解。
   - 表格是多维逐格信息的承接方式，也是难以图解内容的兜底，不与图形竞争同一优先级。
   - 一个图里的**核心信息**（结论、转折、对比）要能一眼看到，装饰性元素不要抢视线。
2. **先理解内容，再自主设计视觉结构。** 先提炼核心结论和读者需要看出的关系，再决定用位置、长度、分组、连接、方向、层级或状态怎样表达。策划时先写视觉组织方案，不要先填图型名称。
   - 每个图都要回答："读者通过它看出了什么关系，减少了什么阅读、回读或对照负担？"
   - 量、差、选、链、层、势、位、态可作为理解内容的检查线索，但不是必须先归入的固定分类。
3. **自主设计优先，语汇库辅助。** 形成独立视觉方案后，再查 `references/vocabulary.md`：能复用就复用，需要调整就改造，复合关系就组合，没有贴切方案就现场设计。**不得为了复用现有组件而改变内容关系或补充数据。**
4. **允许重组与合并。** 先梳理成若干议题，表达同一关系的多个点合并成一个图。**不需要每个图对应一段原话**，也不必机械逐句对应。
5. **以原文含义为基础，允许提炼、概括、重组和适度解读。** 主要精力放在读者能否快速理解上，不编造、不曲解，不额外添加证据等级或制作说明；引号只用于原话，意译不加引号。尤其不要把“我觉得、可能、应该、多数、当前、尚未”等推测或限定，在标题、结论条和图内短标签中压成确定事实或全称判断。
6. **图形化优先，文字解释从简。** 图块数量不设硬性目标；必要注释用于说明口径和边界，正文不要重复图中已经表达的信息。

## 二、流程

### 第 1 步：读内容，判断场景
- **先判断交付模式：**
  - **独立报告**：没有宿主页面，或用户要求完整单文件报告。本 Skill 负责内容、图形和整页实现。
  - **嵌入模式**：已有 HTML 只需局部图解，或用户明确由其他 Skill 负责设计排版。输入为原文、宿主 HTML 和目标位置；本 Skill 只负责内容、图形语义与图内结构，页面配色、字体、间距、响应式布局和整体构建服从宿主。
- **完整材料**（MD、报告）：以它为唯一事实来源，允许正常提炼与重组。
- **输入质量差不改变流程，只决定要不要问一句。** 转写重复、断句错误、明显口误按语义直接整理，不逐条标注；只有关键数字、关键结论或归属在上下文里确实无法判断时，才向用户确认。
- 一段话：直接图解，通常 1–3 个图块。

### 第 2 步：做"图解策划"（**必须先输出给用户，简短**）
先完成内容理解和独立视觉设计，再查语汇库。用一张简表，一行一个议题：

| 核心结论 | 读者需要看出的关系 | 视觉组织方案 | 复用 / 改造 / 组合 / 自创 |
|---|---|---|---|

- 议题标题直接说发现（如"自述与后台对不上，原因未证实"），不要只写主题名。
- **先写视觉组织方案，再填写语汇复用方式**；不要从 V 编号或图型名称倒推内容。
- 适合图解的议题不得无故退回纯文字或表格；难以图解时说明原因再承接。
- 说明哪些点被合并、哪些被舍弃。
- 用户未明确要求"直接做"时，可以在策划后请用户确认；用户说"直接生成"则跳过确认。

### 第 3 步：按模式生成

#### A. 独立报告：写源文件 `<名称>.src.html`
1. 以 `examples/vocab-showcase.src.html` 的基础 `<head>` 为工程参照（含 `<link rel="stylesheet" href="kit.css" data-ve-kit>`，**必须保留**）。示例只用于理解写法，**不得把其中的图形选择当作默认答案**。
2. 页头：`eyebrow` + 结论式 `h1` + `intro`（图例 `ev-legend` 仅在原文确有推测/设想时才加）。
3. 按议题顺序写 `part-head`（PART 分段）与 `section.mod`（卡片）。
4. 每个卡片：`h2` 结论式标题 → 1–2 句说明 → 图 → `insight` 提示条（可选）。
5. 按既定视觉方案选择语汇 class（见 `assets/vocab.css`），或改造、组合、自创；需要时用内联 SVG，并给 `<svg>` 写 `aria-label`。曲线类图用 `scripts/curve.mjs` 生成 SVG 路径，不要手写坐标（见 `references/vocabulary.md` V18/V23）。**SVG 内文字至少 14 个 viewBox 单位；同一行文字不要互相重叠，轴标题和刻度标签放在不同行。**
6. 最终 HTML 只保留读者需要的内容与图形。合并、舍弃、存疑、示意口径和制作过程等信息统一在交付对话中说明；除非用户明确要求，正文不添加"整理说明"、制作备注或方法说明。

#### B. 嵌入模式：只写宿主目标位置的图形片段
1. 不创建完整 `<html>`、`<head>`、页头或页面分区，不修改目标位置之外的 HTML、全局变量、脚本和其他版块。
2. 图内节点位置、比例、轴向和连线仍按内容关系设计；输出局部 HTML 或 SVG，保留必要的标签、数字、图例和 `aria-label`。
3. 优先复用宿主已有 class、CSS 变量和组件，不引入 `kit.css`、`recap-theme.css` 或整份 `vocab.css`。确需新增结构样式时，只写目标容器内的局部作用域样式，颜色与字体沿用宿主。
4. 不新增外部依赖。正文只保留读者需要的内容与图形，制作说明留在交付对话中。

### 第 4 步：构建与检查

#### A. 独立报告
```
node <skill目录>/scripts/build.mjs <名称>.src.html
```
一条命令完成：渲染 → 主题注入（去外链）→ 浏览器视觉检查。必须：
- 视觉检查无 `✗`；有则按提示修改源文件后重跑，**不要重写整页**。构建脚本以电脑端为准，390px 窄屏下的"图内小字号"仅作提示。
- **亲自看截图**。联系表（`.sheet.png`）只覆盖首屏，整页需运行：
  ```
  node <skill目录>/scripts/shoot.mjs <名称>.html <截图目录> 1400
  ```
  并逐张查看：文字是否被截断、元素是否遮挡、图与结论是否一致。**重点看读者扫一眼能否说出关系、是否减少阅读阻力；再快速检查有没有明显说反、说过头或造成误读，优先核对推测语气，以及标题、结论条和图内短标签中的限定词。只在关键数字、引语、人物归属或存疑处回查原文。**
- 发现明确问题再修改，不做逐条来源审计或单独的视觉合规清单。

#### B. 嵌入模式
- **不要运行本 Skill 的 `build.mjs` 注入主题。** 使用宿主既有构建与预览流程；宿主没有构建流程时，直接在浏览器打开最终宿主 HTML。
- 确认目标位置之外未被改动、没有新增外链，并亲自查看图形容器：关系是否清楚，文字是否遮挡或截断，图形是否在宿主桌面与窄屏容器中可读；同时检查图与结论是否一致，推测和限定是否被压成确定事实，关键数字、引语、人物归属及存疑处回查原文。整页视觉回归由宿主流程负责。
- 发现图形语义或图内结构问题再修改片段；发现整页设计问题交回宿主流程，不通过覆盖宿主样式解决。

### 第 5 步：交付
- 独立报告：用 `preview_url` 给用户看；若用户需要文件，用 `deliver_attachments` 交付 `.html`。
- 嵌入模式：把图形片段及插入位置交回宿主流程；若已直接修改宿主文件，说明修改位置，不再另做一套独立主题预览页。
- 回复里只说明对用户有用的合并、示意或存疑；没有需要说明的，不额外罗列制作过程。

## 三、写作要求
- 中文，简洁，无空泛套话。标题用结论句，避免"关于……的分析"。
- 不写诸如"综上所述""值得注意的是"一类衔接语。
- 一段话一个意思，最长不超过 3 句。

## 四、环境与依赖
- 需要 Node 20+；视觉检查需要本机 Chrome 或 Edge；`engine/node_modules/playwright-core` 已随包提供。
- **不访问外网**（字体用系统微软雅黑，不加载 CDN）。
- `engine/` 是第三方开源项目 visual-explainer（MIT）的渲染内核，**不要修改**。来源与许可见 `engine/LICENSE`、`NOTICE.md`。
- 主题与语汇样式在 `assets/`，仅在独立报告中由 `scripts/zh-adapt.mjs` 注入产物，不改引擎源码；嵌入模式不自动注入。

## 五、常见问题
- **视觉检查提示标签小于 12px**：SVG 内文字至少 14 个 viewBox 单位；不要在主题里把图内字号改小。
- **"0 figures" 提示**：本技能的 HTML/CSS 图不是 `<figure>`，提示可忽略，但仍需人工目检。
- **用户要求参考某风格/颜色**：独立报告改 `assets/recap-theme.css` 的变量，不要在每个页面里手写；嵌入模式遵循宿主样式，不改这套主题。
- **没有 playwright/Chrome**：构建会跳过视觉检查并提示；此时必须自己用 `shoot.mjs` 之外的方式确认，或告知用户未经浏览器检查。
