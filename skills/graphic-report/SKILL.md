# 图解报告（graphic-report）

把内容变成**读者一眼能看懂、看完还记得住**的 HTML 页面或图形片段。先理解内容，再设计能表达其关系的画面；组件库是辅助，不是答案。

## 一、工作原则（先读）

### 内容忠实是底线，视觉形式可以自由

- 以原文为唯一事实来源，允许提炼、概括、重组和适度解读；不编造事实、数字、归属、因果或证据等级。
- 保留“我觉得、可能、应该、多数、当前、尚未”等推测和限定，尤其不能在标题、结论条、图内短标签中压成确定事实或全称判断。引号只用于原话，意译不加引号。
- 关键数字、引语、人物归属和存疑处回查原文。原文的比喻、类比和场景是一级视觉素材；适合成图时优先转成图，不因压缩正文而直接删除。
- **构图可以自由。** 用非对称、辐射、收窄、闭环、泳道、层叠、场景或前后变化表达真实关系；用位置、大小、线型、粗细和颜色体现主次。没有数值依据时不补刻度，定性大小标“示意”。装饰不抢核心结论，形式创新不改变事实。

### 图形化优先，删减重复而不压制表达

1. 启用本技能即代表用户希望尽量图形化。适合图解就必须画，只有难以清晰、忠实地图示时才用文字或表格承接；不再以“纯文字是否已经够清楚”为前置门槛。
2. 图形化包括数据、分组、层级、对照、路径、状态、位置、机制、场景和视觉强调。表格承接多维逐格信息，也是难以图解内容的兜底。
3. 每图回答：“读者看出了什么关系，减少了什么阅读、回读或对照负担？”图若只是复述相邻正文，就删图或删重复正文，以阅读收益决定保留哪侧。
4. 同一关系的多个点可合并成一图，不必逐句对应或规定图块数量。文字补充图无法承载的限定、证据和来源。
5. 多图报告按核心关系建立阅读主次；需要主视觉时，让承载核心关系的图获得更充分的空间或构图。平行关系、短内容或简单任务不强行设置 hero，其余图按各自表达需要选择宽度、密度和形态。

## 二、流程

### 第 1 步：读内容，判断场景

- **独立报告**：没有宿主页面，或用户要求完整单文件报告。本 Skill 负责内容、图形、视觉方向和整页实现。
- **嵌入模式**：已有 HTML 只需局部图解，或用户明确由其他 Skill 负责设计排版。输入为原文、宿主 HTML 和目标位置；本 Skill 只负责内容、图形语义与图内结构，页面设计服从宿主。
- 完整材料（MD、报告）作为唯一事实来源。转写重复、断句错误和明显口误按语义整理；只有关键数字、结论或归属确实无法判断时才询问用户。
- **区分事实忠实与逐字保留。** 默认忠实原意并允许提炼重组。用户明确要求不删改原文时，完整保留正文，图只承担跨段关系整合、导航或摘要，不逐段复写；已有宿主优先嵌入，没有宿主采用“正文为主、少量关键图”的混合报告。
- 一段话直接图解，通常 1–3 个图块。

### 第 2 步：做图解策划与视觉构思（先简短输出给用户）

先用一张简表说明内容组织，一行一个议题：

| 核心结论 | 读者需要看出的关系 | 视觉主角、场景与几何 | 实现 |
|---|---|---|---|

- 议题标题直接说发现，不只写主题名；先写画面，再查 `references/vocabulary.md`，不从 V 编号或组件名倒推内容。
- 对每个核心议题先确定焦点、对象、关系和边界，再确定视觉主角与场景，用 `references/design.md` 组织画面；不从 V 编号、图型名称或相似题材成品倒推内容。
- 关系明确时直接设计。只有主视觉焦点不清、方案雷同或实现退回文字容器时，才比较两个候选；候选须改变视觉编码或观察视角，而非只换配色、圆角或排列方向。用一句话说明选择依据。
- 需要自由几何时先画 ASCII 草图，安排节点、连线、标签和留白。实现方式按表达需要选择，不预设某种技术或图型更高级。
- 多图报告避免相邻图同构。等宽横排只用于各项同等重要且无分叉、筛选、主次或角色差异的内容；不要为了形式变化牺牲关系保真。
- 每个图块只承担一个主要阅读任务；场景载体、拆合图和通用容器检测统一按 `references/design.md` 的“场景载体与阅读任务”执行。
- 独立报告将**语义结构与视觉母题分开**：结构来自对象和关系；母题来自题材的材质、工具、符号与阅读习惯。读取 `references/design.md` 和 `engine/references/style-guide.md` 选择 register；节点关系图读取 `engine/references/kit.md`，自由 SVG 构图读取 `engine/references/diagrams.md`。
- 说明合并与舍弃。用户未明确要求“直接做”时可在策划后请用户确认；“直接生成”则跳过确认。

### 第 3 步：按模式生成

#### A. 独立报告：写源文件 `<名称>.src.html`

1. 以 `templates/base.src.html` 为工程起点，保留 `<link rel="stylesheet" href="kit.css" data-ve-kit>`。组件展示和评测案例不是新任务的图形选择或页面模板。
2. 页头用 `eyebrow` + 结论式 `h1` + `intro`，把核心问题或主视觉放在读者的第一条阅读路径上；图例 `ev-legend` 仅在原文确有推测/设想时添加。
3. 按议题顺序组织内容，四个以上章节可加 `nav.ve-toc`。`part-head` 只用于真正的大章节分组，不与紧随的 `h2` 重复；`section.mod` 只在 `data-theme="recap"` 的复盘报告中使用，不强制每节一卡，不在卡片里再套卡片。
4. 每议题以结论式 `h2` 引领。图能表达的关系不写同义正文；逐字保留任务按第 1 步的混合策略处理。
5. **每个独立图块都以 `<figure>` 为最外层容器**，HTML/CSS 图也一样；图注放 `<figcaption>`。按语义选择实现：
   - 节点、区域、连线及其组合优先用 `<ve-flow>`，让引擎计算布局，写法见 `engine/references/kit.md`。
   - 自由几何、共享坐标、形态转换或场景结构用原生 SVG 基础元素，保留清晰 `<g>` 分组、真实 `<text>` 和 `aria-label`，不把文字转路径。
   - 简单并列、短清单、指标和轻量对照用 HTML/CSS；多维精确信息用表格；数值关系使用合适的量化语汇。能用简单实现表达清楚时，不为了“像图”而升级技术。
   - 曲线用 `scripts/curve.mjs` 生成路径。
6. SVG 内文字至少 14 个 viewBox 单位，预留文字、节点和连线的几何空间。直接标注放在对应元素附近，避免靠图下长段解释。主视觉只设一个焦点，强调色用于关键节点或路径；其余保持中性。
7. 最终 HTML 只保留读者需要的内容与图形。合并、舍弃、存疑、示意口径和制作过程在交付对话说明；除非用户要求，正文不添加整理说明、制作备注或方法说明。

#### B. 嵌入模式：只写宿主目标位置的图形片段

1. 不创建完整 `<html>`、`<head>`、页头或页面分区，不修改目标位置之外的 HTML、全局变量、脚本和其他版块。
2. 图内位置、比例、轴向和连线仍按内容关系设计；输出局部 HTML 或 SVG，保留必要标签、数字、图例和 `aria-label`。构图与审美目标同独立报告，但不强设整页 hero 或主题。
3. 优先复用宿主已有 class、CSS 变量和组件，不引入 `kit.css`、`base-theme.css`、`recap-theme.css` 或整份 `vocab.css`。确需新增结构样式时，只写目标容器内的局部作用域样式，颜色与字体沿用宿主。
4. 不新增外部依赖。正文只保留读者需要的内容与图形，制作说明留在交付对话中。

### 第 4 步：构建、看成品、重画最弱图

#### A. 独立报告

```
node <skill目录>/scripts/build.mjs <名称>.src.html
```

一条命令完成渲染、主题注入（去外链）和桌面浏览器检查：

- 视觉检查无 `✗`；有则按提示修改源文件后重跑，不重写整页。默认只检查 1280px 桌面视口，保留 CSS 自然响应式，不另做移动端验收。`⚠` 是构图复查线索，不是硬失败。
- **首轮看完整联系表**（`.sheet.png`、`.sheet-2.png` 等），确认所有图块被收录。先按 `references/design.md` 的好图标准检查：焦点、形状与关系、主次、图间节奏、记忆点和直接标注；再检查截断、遮挡、图与结论、推测和限定。只在关键数字、引语、人物归属或存疑处回查原文。
- 逐图回答效果三问：画面是否贴题且可记忆；主要关系能否在通读全部标签前看出；画面是否由本篇对象与关系决定。第三项用“替换为另一题材文字”测试，若仍完全成立，回到第 2 步重新设计。
- 若主视觉没有清晰焦点、图形与真实关系不符、连续图块同构或某图明显只是文字卡片，**主动重画最弱的 1–2 张**，而不是只修缺陷。最多两轮；已能清楚表达关系且有合理视觉主次时停止，不为分数或风格差异反复改版。
- 联系表遗漏图块、提示内容被省略，或非图块版面需要检查时，再运行整页截图：
  ```
  node <skill目录>/scripts/shoot.mjs <名称>.html <截图目录>/round-01 1400
  ```
- **首轮之后只按改动范围复检：**
  - 图内局部修改照常 build，人工只看受影响图：`node <skill目录>/scripts/shoot.mjs <名称>.html <截图目录>/round-02 1400 --figure=N`。
  - 仅改文字且桌面布局未变，由 build 复查；局部布局也受影响时用 `--selector="CSS选择器"`，选择器须恰好匹配一个元素。
  - 只有全局主题、CSS 或整体布局变化才重新查看完整联系表；确需全页时再分段截图。每轮用新截图目录，保留异常证据。
- 截图空白、位置不符或状态不一致时，先记录文件和元素 DOM 位置、尺寸，再做一次针对性复查；仍无法判断就保留证据并报告，不连续全页重建和整批重读。

#### B. 嵌入模式

- 不运行本 Skill 的 `build.mjs` 注入主题。使用宿主既有构建与预览；没有构建流程时直接在浏览器打开最终宿主 HTML。
- 确认目标外未改动、没有新增外链，亲自查看图形容器：关系清楚、文字无遮挡截断、桌面可读、焦点明确；同时核对图与结论、推测限定、关键数字、引语、人物归属及存疑处。整页视觉回归由宿主流程负责。
- 发现图形语义、图内结构或构图问题再修改片段；整页设计问题交回宿主流程，不覆盖宿主样式。

### 第 5 步：交付

- 独立报告：有 `preview_url` 时用于预览，有 `deliver_attachments` 时用于交付；否则返回最终 `.html` 的可访问路径或文件链接。
- 嵌入模式：把图形片段及插入位置交回宿主；若已直接修改宿主，说明位置，不另做独立主题预览页。
- 回复只说明对用户有用的合并、示意或存疑；无需说明时不罗列制作过程。

## 三、写作要求

- 中文，简洁，无空泛套话。标题用结论句，避免“关于……的分析”。
- 不写“综上所述”“值得注意的是”一类衔接语。
- 一段话一个意思，最长不超过 3 句。

## 四、环境与依赖

- 需要 Node 20+；视觉检查需要本机 Chrome 或 Edge；`engine/node_modules/playwright-core` 随包提供。
- 不访问外网，字体用系统字体，不加载 CDN。
- `engine/` 是第三方开源项目 visual-explainer（MIT）的渲染内核，不要修改。来源与许可见 `engine/LICENSE`、`NOTICE.md`。
- 中文基础主题在 `assets/base-theme.css`，复盘卡片层在 `assets/recap-theme.css`，语汇样式在 `assets/vocab.css`。独立报告由 `scripts/zh-adapt.mjs` 注入；嵌入模式不自动注入。

## 五、常见问题

- **视觉检查提示标签小于 12px**：SVG 内文字至少 14 个 viewBox 单位，不用缩小字号解决空间不足。
- **“0 figures”提示**：纯文字报告可忽略；若确有图块，把每个独立图块改为 `<figure>`。旧稿中的 `<div class="diagram">` 会被桌面构建拦截。
- **用户指定风格/颜色**：独立报告在基础主题变量或页面局部主题层调整，不为每个组件重复写一套；嵌入模式遵循宿主。
- **没有 playwright/Chrome**：构建会跳过视觉检查并提示；此时用其他浏览器方式确认，或告知用户未经浏览器检查。
