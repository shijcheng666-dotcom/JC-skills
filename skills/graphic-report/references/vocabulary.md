# 图形语汇库：九份参考与外部视觉方法

> 用法：先理解内容并独立形成视觉方案，再查下表看能否复用、改造或组合；不贴切就现场设计。
> 语汇库不是模板：目标是**让读者扫一眼就懂**。适合图解的内容必须画，难以图示说清楚时才用文字或表格承接。
> 独立报告可参考 `assets/vocab.css` 实现；嵌入宿主 HTML 时只复用关系与结构，样式由宿主承接，不整份引入语汇 CSS。

## 零、实现索引（完成关系与画面后查阅）

先用 `references/design.md` 确定焦点、关系、视觉主角与场景，再按已知表达需要查找实现。组件只负责承载原方案；采用组件时，须能说明它如何减少理解或对照成本。

| 表达需要 | 可用实现 | 使用边界 |
|---|---|---|
| 一组对象各自的上限 | **V22 上限刻度条** | 统一刻度，条长来自原始值；未覆盖区域不表示数值为零 |
| 随时间逐渐变稳或变化 | **V23 衰减波形**、V18 其他曲线 | 有真实方向或序列；只有两点时不伪造中间曲线 |
| 几部分各占多少 | V01 占比条 | 各项共享同一总量与口径，未知不补零 |
| 同一批对象在两种口径下不同 | V03 来源对照条 | 两种口径可以同基准比较，不把差异自动解释为因果 |
| 从强到弱、从多到少的分层 | V04 阶梯分层 | 层级有原文依据，不把类别变成排名 |
| 一个对象落在弱—强的位置 | V05 强度光谱 | 定性位置不补数值刻度 |
| 有覆盖不到或看不见的区域 | V06 缺口对照、V04 的虚线盲区 | 缺口边界有依据，不用面积暗示精确数量 |
| 两条信息互相冲突 | V07 矛盾对照 | 双方对象、条件和比较口径清楚 |
| 同一对象因条件走向不同结果 | V10 条件分支、V09 规则与例外 | 条件与结果有真实对应 |
| A 导致 B 导致 C，并带转折 | V12 因果链 | 每段方向有依据，推测保留限定 |
| 一个流程的步骤与分叉 | V14 行为路径、V15 阶段演变 | 确有顺序与分支，不把句子拆格当作流程 |
| 空间或界面里的位置分布 | V19 布局示意 | 位置本身承载信息，不做装饰插图 |
| 多个判断的成熟程度不同 | V21 状态看板 | 状态口径明确，不把阶段当作评分 |
| 总数量很大，核心只是其中一小部分 | V24 总量—核心子集 | 包含关系真实，数量可回查 |
| 同时看自述强度与实际行为 | V25 自述—行为双轨 | 两种口径对应同一对象和时期 |
| 多步链路只有一环异常 | V26 链路断点定位 | 断点位置有依据，未知不标成异常 |
| 各类别数量同时存在零值或未知 | V27 计数分布 | 零与未知分开，数量由原始记录计算 |
| 阶段中同时看行为、想法和情绪 | V28 用户旅程 | 同一阶段内各轨同步，不把并列信息硬排成先后 |
| A 与 B 双向强化或削弱 | V29 反馈回路 | 确有反馈进入下一轮，不把线性流程首尾相接 |
| 按两个维度定位多个对象 | V30 二维定位 | 两轴独立且有依据，定性位置不补刻度 |

表格适用于多维、需要逐格核对的精确信息。高低、快慢、先后、强弱等方向性关系，只有图形能减少理解或对照成本时才绘制。

## 二、实现要点

### 量
- **V01 占比条**：单条横向堆叠，各段加粗标注占比；小段的标签下移避免挤压。
- **V02 时长对照条**：横轴为共同刻度（小时），区间画成色块的起止；刻度线浅色。
- **V03 来源对照条**：每项两条细条（口径一/口径二），用不同色深区分；差异大的项加标签。
- **V04 阶梯分层**：条长递减、透明度递减；最后一格可用**虚线空框**表示“看不见的盲区”。
- **V05 强度光谱**：一条渐变线 + 三个以上圆点 + 下方对应文字列；两端写明方向。
- **V22 上限刻度条**（`.ceil`）：
  - 每项一行：左上名称，右上一句话原因，下方一条轨道。
  - 轨道里的**实心条长度 = 能到的上限**，右侧用**斜纹块**（`.gap`）表示“够不着的区间”。
  - 底部加共同刻度（0 / 3 分 / 4 分 / 5 分）；5 分处高亮并标“核心关注”。
  - 同一类的几项可以用同一色深；更低的上限用更浅色。条内可用 `.in` 加小标注（如“多数到这里”）。
  - 只有原文提供可解释的数值上限时才画条长；“很少到 5 分”“不太可能到 5 分”不能自动换算成 4 分，没有分值的类别不进入刻度图。
  - 参考 s9-5，**用条长直接表达有依据的分数高低**，未给数值的定性判断另用文字或组合图承接。
- **V24 总量—核心子集**（`.subset`）：左侧大数字表示总量，箭头收束到右侧核心子集；子集内可再拆构成。总量、子集和“约数／推算”口径分开写，不把不同统计范围混成同一漏斗。
- **V27 计数分布**（`.countdist`）：各类别共用计数刻度，零值用空轨、未知用虚线轨道，二者文字也必须标明。未知不计作零，也不纳入完整百分比；归一化条长需说明比较口径。

### 差
- **V06 缺口对照**：左右两个区块 + 中间虚线与“覆盖不到”字样；右侧用虚线框表示“难以量化”。
- **V07 矛盾对照**：两格之间居中放 `≠`；格内标注来源（自述 / 后台）。
- **V08 偏差矩阵**：三列（情形 / 后台读到 / 真实心理），行末加“低估/高估”徽标。
- **V25 自述—行为双轨**（`.dualtrack`）：同一对象一行，实色条表示行为或后台信号，虚线轨表示自述强度。适用于两种口径需要并置，而不是只能判定“矛盾”的情况；定性条长必须标明仅表相对强弱。

### 选
- **V09 规则与例外**：左“默认”，右“例外”，例外卡片用强调色，下方写触发原因。
- **V10 条件分支**：根节点 → 条件胶囊 → 结果叶子；命中分支用强调色加 ✓，未命中用中性色。
- **V11 形态对比**：来源块 → 向下箭头 → 两行对比（✕ 被抵触 / ✓ 可接受），右侧小标签说明原因。

### 链
- **V12 因果链**：横向节点（每个带“过去/近期/信号层”小标签）+ 细箭头；下方放“但是……”转折条。
- **V13 条件链**：左侧并列条件（门） → 箭头 → 结果；条件之间的关系（“且”）要显式标注。
- **V14 行为路径**：竖向或横向的步骤，分叉处用条件胶囊。
- **V15 阶段演变**：横向阶段卡片，每张写“关注点”；阶段之间的触发条件写在箭头上。
- **V26 链路断点定位**（`.chain` + `.nd.warn`）：正常节点保持中性或通过态，只把异常节点标成警示色。结论限定在已核对的案例和环节，不从一个断点推断整条链路或整个系统失效。
- **V28 用户旅程**（`.journey`）：顶部阶段带对齐下方行为、想法等行，情绪曲线单独占一行并与阶段共用横轴。只呈现材料提供的信息；没有情绪或想法依据时省略对应行，不补写。
- **V29 反馈回路**（`.loop`）：节点与闭环箭头共同表达双向作用，箭头旁写明“强化／削弱”及具体关系。只有材料明确支持双向作用时使用，不把单向因果链首尾硬连。

### 层
- **V16 门槛阶梯**：上层“默认”，下层“少数”，中间用 ↓ 与“满足条件才升级”连接。
- **V17 结构拆分**：整体 → 子类卡片网格；子类内部再分用嵌套小标签。

### 势
- **V18 时间曲线**：一条 SVG 曲线 + 浅色基线 + 高亮带 + 少量标注。路径用 `scripts/curve.mjs` 生成（`bump`=冲高回落，`pulse`=脉冲，`rise`=爬升）。
- **V23 衰减波形**（`.wave`，SVG）：
  - 一条**连续曲线**：左端大幅起伏，振幅逐渐衰减，最终趋于平直。路径用 `node scripts/curve.mjs wave --x 70,640 --y 150 --amp 62 --cycles 4.6 --decay 0.85` 生成，末端补一段直线 `L730,150`。
  - 左侧用浅色区块圈出“波动大”的新手期；基线用虚线；横轴下方标阶段（新手期 / 逐渐聚焦 / 成熟期），**轴标题放在另一行，不与阶段标签并排**。
  - 顶部左右各放一个小标题＋一句说明，把两种状态点名，**不用画线遮挡文字**。
  - 参考 s9-7：一条波浪线就把“先乱后稳”讲完了，比并排卡片直观得多。

### 位
- **V19 布局示意**：用真实空间排布（如 4 页桌面，每页一个点阵）；已知的部分着色，**“未提及”显式标灰**，不得猜测。
- **V20 对应连线**：左列对象，右列落点（平台/类别）；右侧用不同色标签区分。
- **V30 二维定位**（`.quad`）：两条轴标明维度与方向，对象放在相对位置。没有精确数据时按定性位置表达，不补刻度、百分比或排名；两个维度必须来自材料或明确是对原文的概括，每个对象的高低方向也须有原文依据，不为版面均衡挪位。

### 态
- **V21 状态看板**：三列“已成立 / 待更新 / 下一步”，列头用圆点；每条结论只放在一列，不重复。

## 三、因地制宜的原则

1. **先有关系，再有图。** 先写出“这段话想让读者看明白什么关系”，再选图；写不出来就不画。
2. **图要比文字更快。** 如果读者看完图还得回头读文字才能懂，说明图没选对。
3. **允许合并。** 口述里分散的几个点如果表达同一关系，合成一个图。
4. **允许组合。** 例如“占比条 + 缺口对照”，“因果链 + 状态标记”。
5. **允许自创。** 语汇库里没有就现场设计；独立报告沿用同一主题，嵌入页面沿用宿主的配色、圆角和字号。
6. **删减重复，不压制表达。** 一页里可保留纯文字段落，图与文字的节奏比图的数量更重要；核心关系值得更完整、更有记忆点的构图。

### 可复用的组合方式（不新增编号）

| 组合 | 用法 |
|---|---|
| 并置 | 两种口径、对象或结果并排对照 |
| 嵌套 | 总体—子类、阶段—行为、问题—子问题 |
| 分叉 / 汇合 | 条件分支，或多因素共同作用 |
| 层叠 | 主图上增加缺口、阈值、状态或标注 |
| 分面 / 小倍数 | 同一结构在多个对象上重复，便于比较异同 |
| 连线 / 映射 | 对象—平台、发现—行动、因素—结果 |
| 序列 | 时间、阶段、流程和优先级 |
| 强调 / 弱化 | 区分核心、异常、未知、背景和待办 |

## 四、关于“证据标记”（可选）

`ev fact / infer / idea`（● 实录 / ◐ 推断 / ○ 设想）是**可选工具**，**默认不用**。仅当原文本身明确区分了“事实”和“猜测/设想”，并且读者需要看出这种区分时才使用。用户给的是结论性内容时，不要添加。

## 五、扩充候选（未实现，仅供设计参考）

> 这些关系在报告中常见，但目前**没有专用组件**。清单不参与生成流程，也不需要在每次产出时读取；只在两种情况下查看：遇到现有 30 种加组合都表达不了的关系，或做版本迭代时集中评估。V28–V30 已转为正式组件，不在此重复。
> **未实现 = 不得当成可用语汇直接套用。** 真正采用时，按“关系是否成立、现有组合是否已够用、能否跨材料复用、是否依赖原文没有的数据”四条判断，再决定写成组件还是继续现场设计。

| 候选关系 | 典型材料 | 现有能力能否覆盖 | 建议 |
|---|---|---|---|
| 一个问题向下分叉出多个原因 | 归因分析、故障复盘 | V10 条件分支 + V17 结构拆分可组合 | 暂不单独做，组合够用 |
| 触点、渠道、行为的对应关系 | 运营/产品链路分析 | V20 对应连线可做两侧映射；三列以上需表格 | 需要时按矩阵现场设计 |
| 总量沿多条路径分流 | 流量/预算/人群拆分 | V01 占比条 + V24 只覆盖“一个整体几部分” | 复杂分流可考虑桑基式画法，谨慎 |
| 逐级流失的漏斗 | 转化分析、招募筛选 | V24 总量—核心子集语义接近，但漏斗强调逐级流失 | 需要时由 V24 改造，不新设编号 |
| 多对象同结构并列看趋势 | 多组对比、分组小倍数 | 靠重复布局即可，不需要组件 | 不设组件，写进布局约定 |
| 带时间刻度的节点序列 | 项目历程、事件脉络 | V15 阶段演变部分可替代 | 暂不单独做 |
| 两类对象的重叠与独占部分 | 人群重叠、标签重合 | 无 | 使用频率低，暂不做 |
| 矩形树图、旭日图、弦图、平行坐标 | 多维占比、关系网络 | 无 | 明确不做：阅读成本高，与“扫一眼就懂”冲突 |

**判断口径**：真实材料中反复出现、且现有组合明显不如专用图清楚的关系优先新增；外部方法里的通用缺口须经展示页实现和验收后再纳入核心。不追求编号数量。

## 六、领域复合组件（按需、数据驱动）

领域组件不进入核心 30 种，也不参与普通文字报告的默认选图。只有数据关系明确、用户场景匹配时才启用。

### 双分母集合覆盖图（含印象切分与盲区）

- **组件**：`assets/set-cover.js`，接口 `window.SetCover.render(target, data)`；`target` 为 DOM 元素或元素 id。
- **演示**：`examples/set-cover-demo.html`，自包含三面板示例。
- **数据**：`sets` 提供集合名称、说明、N、有印象比例（可选）；`panels` 提供集合布局、交集人数与盲区人数。百分比必须由人数 ÷ 对应 N 计算，不手写。
- **适用**：模型判定与用户自述对照、集合覆盖与盲区分析。椭圆和交集面积为结构示意，不表达精确面积比例。
- **边界**：交集人数不得超过任一集合 N；有印象比例不得由交集推算；三集合盲区只有在互斥关系明确时才可计算，否则须单独提供；超过三个集合时重新设计，不直接套用。
