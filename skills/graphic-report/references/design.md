# 视觉推导与好图标准

独立报告或需要重新设计图内构图时读取。目标是从任意材料中推导表达，而不是寻找与题材相似的成品加以改编。

## 一、先确定读者需要辨别什么

每个核心议题先用简短语句确定：

- **焦点**：读者首先应该注意到哪个对象、变化或差异？
- **对象**：哪些实体必须出现，各自有哪些与表达有关的真实属性？
- **关系**：方向、基数、包含、顺序、并行、状态、转换或数值关系是什么？
- **边界**：哪些推测、限定、未知和例外必须在图中保留？
- **阅读收益**：这幅图减少了什么回读、对照或想象负担？

只编码材料支持的关系。大小、位置、线型、数量和形状都具有含义，不能为了构图完整补上原文没有的信息。

## 二、场景载体与阅读任务

关系确定后，先选择**视觉主角**：读者要跟踪的是对象、界面、数值、路径还是位置。原文存在能承载关系的具体对象、界面或空间时，优先让它的分区、位置和变化组织布局；没有天然场景时，再用轴、距离、包含、分岔等抽象几何。场景必须减少想象或对照成本，不能只增加装饰。

场景载体与视觉母题不同：场景改变布局与阅读动作，母题只提供材质、符号和排版细节。删去装饰后，主要关系仍应成立。

每个图块只回答一个主要问题。需要回答不同问题、采用不同阅读顺序时拆图；共享对象、场景或比较轴且需要相互对照时合图。图块数量不设目标。

一句话拆格、观点间加箭头、主题排两列都只是排版起点；只有原文分别支持顺序、因果或对照时，才形成流程、因果链或对照图。完成草图后做**换词测试**：若只替换标题和标签就能原样用于另一题材，重新检查视觉主角、几何和阅读动作是否真正来自本篇内容。

## 三、用视觉编码算子组合画面

算子是构图的基本动作，不是完整图型。根据读者需要辨别的关系选择并组合，不从名称出发套模板。

| 视觉编码 | 可以表达 | 使用边界 |
|---|---|---|
| **位置与对齐** | 主次、次序、共同基准、对象之间的对应 | 没有依据时不借上下左右暗示排名、高低或先后 |
| **连接与方向** | 作用、传递、依赖、回流、交接 | 连线类型和方向必须来自材料，不把相邻对象自动连成因果 |
| **分支与汇合** | 一对多、多对一、条件路径、共同结果 | 基数必须真实；仅存在多个对象时不自动暗示中心控制 |
| **包含与边界** | 所属、隔离、层级、职责范围、内外差异 | 边界不暗示原文没有的安全、物理或组织隔离 |
| **分区与轨道** | 并行角色、独立过程、跨区域交互 | 分区维度应稳定，不能每个区域换一套比较口径 |
| **共享坐标与小倍数** | 状态变化、对象间异同、前后或条件对照 | 保持相同尺度与位置含义，只突出真正变化的部分 |
| **形态转换** | 输入到输出的改变、筛选、聚合、拆分 | 没有数量时不以面积或密度暗示精确比例 |
| **层叠与跨越** | 支撑层级、跨层作用、主路径与旁路 | 层叠不自动表示优劣、时间或调用顺序 |
| **长度、面积与刻度** | 有依据的数量、比例、区间和差异 | 数值、单位和比较口径必须可追溯，定性关系不补刻度；数值驱动的位置、长度与间距由原始值计算，不目测百分比，非比例轴明确标注 |
| **强调与弱化** | 焦点、关键路径、异常、未知或背景 | 强调应有明确语义；颜色之外保留形状、线型或文字线索 |

组合时先保证主要关系，再添加次要信息。若两个算子传达同一关系，保留阅读成本更低的一个。

## 四、需要时比较候选，不表演构思过程

关系明确时直接设计。只有主视觉焦点不清、方案明显雷同或实现退回文字容器时，才比较两个候选。

候选之间应改变**视觉编码或观察视角**，例如从对象连接改为状态对照，而不是只换配色、圆角、排列方向或组件皮肤。选择依据只需一句：哪个方案更忠实、更容易理解，以及为什么。

原文中的类比可以提供观察视角，但必须保留真实对象和关系；类比不是独立事实来源。题材影响视觉母题，不预先决定图形结构。

## 五、语义结构与视觉母题分开决定

- **语义结构**来自对象与关系，由上述算子组织。
- **视觉母题**来自题材的材质、工具、符号和阅读习惯，只影响适度的颜色、底纹、线条、图标和排版细节。
- 母题不能改变事实，也不能成为跨材料复用的固定签名。删去母题后，主要关系仍应成立。

Register 按阅读任务选择：Blueprint 适合结构与系统，Paper 适合概念与长阅读，Instrument 适合审计、指标与状态，Editorial 适合叙事与展示。具体规范见 `engine/references/style-guide.md`。

## 六、按表达需要选择实现

| 内容形态 | 优先实现 |
|---|---|
| 节点、区域、连线及其组合 | `<ve-flow>`，写法见 `engine/references/kit.md` |
| 自由几何、共享坐标、形态转换或场景结构 | 原生 SVG 基础元素，规范见 `engine/references/diagrams.md` |
| 简单并列、短清单、指标和轻量对照 | HTML/CSS |
| 多维、需要逐格核对的精确信息 | 表格 |
| 有数值依据的量、差、势和分布 | `references/vocabulary.md` 中合适的量化语汇 |

实现方式不构成质量目标。能用简单 HTML 表达清楚时，不为了“像图”而改成 SVG；需要自由几何时，也不为了省坐标而退回等宽卡片。

## 七、好图与停止条件

首轮看实际成品，检查：

1. 遮住正文后，图形的主要焦点与关系是否仍然可辨认？
2. 每个位置、连接、边界、形态和强调是否有事实或明确的示意依据？
3. 是否减少了读者的理解、回读或对照成本，而非仅把文字换成容器？
4. 主次是否清楚，相邻图的观察方式是否服务各自关系？
5. 标注是否贴近对象，推测、未知和限定是否仍然可见？
6. 是否存在更简单的实现可以表达同一关系？

若焦点不清、关系说错或图块只是换皮文字，重画最弱的 1–2 张，最多两轮。关系正确、焦点清晰、文字无遮挡截断、事实未退化后停止；不按技术栈、图型名称或页面高度评分。
