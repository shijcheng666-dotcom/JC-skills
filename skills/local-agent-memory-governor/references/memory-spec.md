# 本地 Agent 长期记忆管理规范

> 交接整理日期：2026-07-28
> 维护者修订：2026-07-31（基于原始规范补齐执行层量化标准）
> 二次修订：2026-07-31（按用户确认调整——①profile 精炼不限固定条数、只给软提示；②raw 快照不烧 token 故默认保留追溯、不主动清空；③低风险自动修剪后必须告知用户）
> 适用对象：本地 Agent AI 助手（及后续接手维护的 AI Agent）
> 核心原则：**项目级信息用后即弃，全局记忆只存跨项目通用规则**

---

## 一、记忆的物理文件结构

```
%LOCALAPPDATA%\local-agent\memory\
├── MEMORY.md              # 系统操作手册，不存用户内容
├── profile.md             # 精简画像（用户偏好 + 助手反馈 + 长期参考）
├── raw/
│   └── memories.md        # 自动保留的原始会话快照，只修剪无价值记录
└── topics/
    ├── user_preferences.md   # 个人偏好（写作习惯、工具喜好、工作风格等）
    ├── assistant_feedback.md # AI 行为反馈（被纠正过的点、工作原则、规范等）
    └── references.md         # 技术参考（路径、命令、配置等）
```

辅助目录（技能维护时自动创建，不影响桌面端记忆注入）：

```
├── backups/                # 修改前完整备份
├── audit-reports/          # 每次审计的报告
└── pending-migration/      # 待迁移到项目工作区的项目级信息暂存区
```

## 二、全局记忆 vs 项目记忆的分工

### 全局记忆（`memory/` 目录）
**保存条件：跨项目长期通用，且未来会反复用到。**
- 个人工作习惯与偏好（报告风格、工具偏好、命名偏好等）
- AI 行为规范与工作原则（三条原则、记忆分工规则等）
- 长期固定的团队关系（同部门同事、直属/隔级领导）
- 固定技术参考（Z盘映射、访问方式、搜索命令、CPU 兼容性等）

### 项目记忆（工作区 `.agent/memory/` 目录）
**保存条件：仅当前项目需要，项目结束后不再复用。**
- 业务方角色与联系人信息
- 项目背景文档路径与链接
- 项目会议纪要
- 项目术语
- 项目研究方案、问卷路径
- 任何项目完结后不再需要的信息

**生命周期：** 与项目工作区共存亡。新项目开新工作区，旧项目工作区自然过期。

## 三、入库决策流程

```
遇到一条新信息，想记下来
        │
        ▼
┌───────────────────────────────┐
│ 这条信息是「跨项目通用」的吗？ │
│ （未来几个项目都可能用到）    │
└───────────┬───────────────────┘
            │
     ┌───是───┴───否───┐
     ▼                  ▼
 写入全局记忆       ┌─────────────────────────┐
 topics/ 对应文件   │ 这是「当前项目专属」的吗？│
                    │（业务方、背景文档、术语等）│
                    └───────────┬─────────────┘
                          ┌───是───┴───否───┐
                          ▼                  ▼
                      写入工作区          ┌────────────────────┐
                      .agent/memory/       │ 这是临时信息吗？    │
                                          │（一次性文献、短期   │
                                          │ 配置变更、技能产物  │
                                          │ 路径、一次性问答）  │
                                          └────────┬───────────┘
                                                   │
                                           ┌───是───┴───否───┐
                                           ▼                  ▼
                                      不写入记忆          按上下文判断
                                      （用完即弃）       （大概率属于项目级）
```

**跨维度信息的归类规则（补充）：** 当一条信息同时涉及多个维度时，按"主要用途"归类：
- 用户个人特征（如"领导偏好理论框架"影响助手行为）→ 归入 `user_preferences.md`，记录为用户事实
- 对 AI 行为的明确要求（如"参谋方案时运用理论框架"）→ 归入 `assistant_feedback.md`，记录为行为指令
- 同一信息如果同时具有"用户事实"和"行为指令"两面，在两处各保留一条，但措辞侧重不同维度，不逐字重复

## 四、全局记忆各文件的分工细则

### 1. `profile.md` — 精简画像

**该放什么：**
- 用户角色与工作性质（如"用研角色，负责定性报告"）
- 核心工作习惯（如"偏好一步步来""偏好理论框架包装"）
- 工具与环境偏好（如"不编程""无CUDA""偏好中文界面"）
- 关键行为规范（三条原则、项目记忆分工规则）
- 长期固定的团队关系（同部门同事、直属/隔级领导）
- 常用固定技术参考（Z盘路径、搜索命令、CPU 兼容性）

**不该放什么：**
- 具体项目的业务方角色与联系人
- 具体项目的文档路径或链接
- 一次性调研文献的引用
- 一次性技能配置信息
- 临时性技术排查记录

**精简原则（用户确认版）：**

profile.md 的画像内容遵守以下原则：

| 约束项 | 说明 |
|--------|------|
| 条数 | 不限定固定上限；确实重要的内容才保留，尽量精炼篇幅，不变成流水账。条数明显偏多（如 > 40 条）时给出软提示，由人工判断精炼空间 |
| 每条长度 | 尽量精炼，单条过长（如 > 80 字符）给出软提示，不强制删减 |
| 与 topics 的关系 | 关键词级引用或高价值摘要，不完整镜像；详细内容只在 topics 文件保留 |
| 身份块 | `<!-- local-agent-company-identity:start/end -->` 区间为系统自动更新，AI 不修改 |
| 画像区间标记 | 用 `<!-- local-agent-profile-summary:start/end -->` 包裹画像部分（身份块之后的内容）。系统登录时识别此标记并跳过该区间，不会用 topics 内容重写。精简后的画像可持久保持。 |

**关键立场：精简是方向，不是硬指标。** 多不等于错，流水账才是错。审计只做"提示可精炼"，删除与否由用户定。

**镜像判定规则：** 如果 profile.md 画像摘要中某条的内容与 topics 文件某条逐字相同或语义完全一致（适用条件也一致），判定为"完整镜像"，属于低风险自动精简对象。精简后保留一行关键词级摘要，指向 topics 中的详细条目。

**回退防护：** 画像部分必须用 `<!-- local-agent-profile-summary:start/end -->` 标记包裹。未加标记时，系统会在每次会话登录时用 topics 内容重写画像部分，导致精简失效。如果审计发现画像条目数异常膨胀且不含此标记，应提示添加标记。

### 2. `topics/user_preferences.md` — 用户偏好

**该放什么：**
- 写作风格偏好（报告框架、语言风格、图表格式）
- 工作方式偏好（分步骤推进、理论框架包装）
- 工具偏好（会议、文件搜索、字体等）
- 环境限制（无 CUDA、管理员权限、安全软件等）
- 命名风格偏好（有立意、有差异化的名称）
- 项目分工规则（项目信息放工作区）

**不该放什么：**
- 与个人偏好无关的行为规则（放到 `assistant_feedback.md`）
- 技术路径与命令（放到 `references.md`）
- 项目级信息

---

### 3. `topics/assistant_feedback.md` — AI 行为反馈

**该放什么：**
- 用户明确纠正过的行为
- 工作原则（三条原则）
- 特定场景的处理规范（会议纪要、任务扫尾、文档修改等）
- 记忆管理规范

**不该放什么：**
- 用户个人偏好（放到 `user_preferences.md`）
- 技术参考（放到 `references.md`）
- 仅一次有效的反馈（如"某次报告某段可以改得更好"）

**去重原则：** 同一条反馈只保留一次，多条重复表述合并为一条。

---

### 4. `topics/references.md` — 技术参考

**该放什么：**
- 固定的系统路径与映射
- 长期使用的 CLI 命令与参数
- 硬件兼容性信息
- 长期使用的工具访问方式

**不该放什么：**
- 项目级文档路径
- 临时性排查记录
- 一次性文献链接
- 技能产物路径
- 任何项目完成后不再需要的信息

**时效性验证（补充）：** 技术参考类信息（如软件版本兼容性、CLI 命令格式）在写入时标注验证日期。超过以下周期未验证的条目，在审计报告中提示"建议验证是否仍然有效"：

| 信息类型 | 建议验证周期 |
|---|---|
| 软件版本兼容性 | 6 个月 |
| CLI 命令与参数 | 12 个月 |
| 固定路径与映射 | 12 个月 |
| 团队关系 | 12 个月 |

---

### 5. `raw/memories.md` — 原始会话快照

**核心立场：** raw 快照存放在硬盘上不烧 token，因为它不参与每次会话的自动注入——只有被人主动读取时才占用上下文。因此默认保留作追溯，不主动清空。

**token 红线：** 真正烧 token 的是被自动注入 AI 上下文。raw/memories.md 始终只作追溯存档、不进入自动注入；一旦发现它被纳入自动注入而推高 token 或影响工作质量，应坚决清理。清理与否由用户确认。

**可修剪的情况（仍需用户确认）：**
- 确认毫无参考价值的会话快照（如纯闲聊）
- 内容已被整理到 `topics/` 对应文件，且证实不再需要原始记录的

**不因以下理由修改：**
- 单纯为了"看起来更干净"
- 为了删除项目级引用（已确认不再需要时可修剪）

**审计不检查 raw：** raw 快照不参与审计流程。审计脚本只统计快照数量用于报告，不做归档判定或清理建议。仅在用户主动要求清理 raw 时，由 AI 临时读取文件做语义判断后处理。

## 五、三条核心原则（适用于所有工作）

### 原则一：工作量不打折，打完折要说
任务里每问一件事，就做好做满。如果某个环节客观上做不到位（文件太长只能跳读、工具限制无法验证等），必须主动告知：哪里检查了、哪里只做了粗略判断、哪里完全没碰。不能自己默默降低标准然后把减量版当完整版交付。

### 原则二：区分"我看到的事实"和"我推断的结论"
输出中的每一个判断，心里默问一句：这一条是从原文找到的，还是我推出来的？如果是推断，就标注推断；如果是事实，就给出证据。事实和推断混在一起 = 欺骗，不管有意无意。

### 原则三：交付物的接受标准
不能因为默认用户是亲历者、是专业研究者、会再复查，就降低交付标准。每一次交付，默认假设是：用户拿到了就拿去用，不再人工复核——在这个标准下，交付的东西是否合格？

## 六、默认判定基线（技能内置）

当用户未在会话中指定外部规范路径时，本规范作为默认判定基线。用户在会话中明确提供的外部规范可覆盖本基线的对应条款。使用外部规范时，审计报告中应标注使用了哪个基线。

本基线覆盖以下判定维度：
- **准入判定**：第三节入库决策流程
- **职责判定**：第四节各文件分工细则
- **去重判定**：逐字相同 = 低风险自动处理；语义等价（信息点+适用条件一致）= 低风险；语义接近（核心信息一致但适用条件/范围不同）= 中风险建议合并
- **精简判定**：profile.md 精简原则（第四节第1条，软提示而非硬上限）
- **时效判定**：references.md 时效性验证周期（第四节第4条）

## 七、名词解释

| 术语 | 定义 |
|---|---|
| 全局记忆 | `memory/` 目录下的所有文件，AI 每次启动都会读取 |
| 项目记忆 | 工作区 `.agent/memory/` 目录下的文件，仅当前项目相关 |
| 项目级信息 | 业务方角色、背景文档、项目术语、会议纪要等，做完即不再用 |
| 跨项目通用 | 个人偏好、工作原则、固定技术参考，未来多个项目都可能用到 |
| 一次性信息 | 临时阅读的文献、短期配置变更、技能产物路径、临时问答 |
| 语义等价 | 核心信息点与适用条件完全一致，仅表述不同 |
| 语义接近 | 核心信息点一致，但适用条件、范围或限定语境存在差异 |

## 八、审计频率与触发条件

| 场景 | 建议频率 |
|---|---|
| 例行审计 | 每月一次 |
| 大项目结束后 | 额外运行一次 |
| 发现注入异常（如 profile 条目数异常膨胀、token 消耗突增） | 即时运行 |
| 自动化定时任务 | 由用户自行设定（如每周/每月固定时间） |

## 九、profile.md 回退防护

**根因（已定位）：** 每次新会话登录时，宿主桌面端自动用 topics 内容重写 profile.md 的画像部分。未加标记时，精简后的画像会在下次登录时被完整镜像覆盖。

**解决方案：** 画像部分用 `<!-- local-agent-profile-summary:start/end -->` 标记包裹。系统识别此标记并跳过该区间，不会重写。已验证有效（2026-08-07）。

**审计检查：** 如果审计发现画像条目数异常膨胀（如从 40 条变为 70+ 条），检查画像部分是否包含 `local-agent-profile-summary` 标记。缺少标记时，提示添加。
