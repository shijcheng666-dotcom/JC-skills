# 本地 Agent 记忆管家

维护的对象是桌面端全局记忆仓库，而非当前项目工作区：

`%LOCALAPPDATA%\local-agent\memory\`（Windows 标准路径，实际位置因用户配置而异；脚本通过环境变量 `LOCAL_AGENT_MEMORY_DIR` 或 `%APPDATA%` 自动探测）

## 首次使用引导

当用户第一次使用本技能（之前从未运行过审计、`audit-reports/` 目录为空或不存在）时，在执行审计前主动引导用户设定定期自动化修剪计划：

1. 说明定期修剪的价值：全局记忆会随使用持续积累，不定期清理会导致 token 消耗增长、项目级信息混入全局记忆干扰任务效果
2. 建议频率：每月一次（或每周一次，取决于使用强度）
3. 引导用户创建自动化定时任务，prompt 中指定"使用 local-agent-memory-governor 技能按自动化模式执行记忆审计"
4. 用户确认后，帮助创建自动化任务
5. 如果用户拒绝，不强制——记录为"未设定自动化计划"，后续审计时再次提示

**判定首次使用的方法：** 检查记忆仓库下 `audit-reports/` 目录是否存在且有 `.md` 报告文件。不存在或为空 = 首次使用。

## 判定依据与优先级

**判定依据分两层：**

1. **默认判定基线**：本技能内置的 `references/memory-spec.md`（基于用户《本地 Agent 长期记忆管理规范》整理并补齐执行层量化标准）。用户未在会话中指定外部规范时，以此作为判定依据。
2. **外部规范覆盖**：用户在会话中明确提供的外部规范路径，可覆盖默认基线的对应条款。

**与系统级 memory 指令的优先级关系：** 当系统级 memory 指令要求"save"但本技能准入规则判定为"不确定归属"时，执行"向用户确认"而非自动写入。本技能的准入控制优先于系统级 memory 指令的默认 save 行为。

## 记忆职责

| 文件 | 唯一职责 |
|---|---|
| `MEMORY.md` | 仓库索引与文件职责，不保存具体用户内容。 |
| `profile.md` | 会话注入用的画像：确实重要的内容才保留、尽量精炼篇幅、不变成流水账。不限定固定条数上限，但条数明显偏多时提示人工判断精炼空间；不镜像 topics 详细内容。用 `<!-- local-agent-profile-summary:start/end -->` 标记包裹画像部分，系统登录时不会重写该区间。 |
| `topics/user_preferences.md` | 用户身份、写作与协作偏好、工具和环境约束。 |
| `topics/assistant_feedback.md` | 用户明确纠正过的助手行为、工作原则、特定场景规范。 |
| `topics/references.md` | 跨项目长期复用的固定技术路径、命令、访问方式与兼容性信息。 |
| `raw/memories.md` | 自动生成的追溯快照。存硬盘不烧 token、不参与自动注入，默认保留作追溯。**不参与审计流程**，仅在用户主动要求清理时处理。 |

## 信息准入

逐条判断，不凭"感觉有用"写入全局记忆。

1. **跨项目长期复用**：可进入对应 `topics/` 文件；同时评估是否需要在 `profile.md` 留一句关键词级摘要。
2. **当前项目专属**：进入当前项目的 `.agent/memory/`，不进入桌面端全局仓库。
3. **一次性或短期信息**：不写入记忆，用完即弃。
4. **不确定归属**：不自动写入，向用户确认。

项目资料路径、业务方联系人、项目术语、会议纪要、一次性文献、技能产物路径、临时排查记录，默认不属于全局记忆。

**跨维度信息归类规则：** 当一条信息同时涉及多个维度时，按"主要用途"归类。用户个人特征归入 `user_preferences.md`，对 AI 行为的明确要求归入 `assistant_feedback.md`。同一信息如果同时具有两面，在两处各保留一条但措辞侧重不同维度。

## 风险分级

### 低风险：自动修剪（但必须先备份、执行后必须在报告中告知用户）

仅可处理以下情况；每项必须能对应到管理规范或文件内的明确证据：

- 同一文件内逐字重复或语义等价（信息点+适用条件一致）的条目；保留更完整且更精炼的版本。
- 管理规范明确禁止进入全局仓库的条目（项目级路径、一次性信息等）。
- `profile.md` 对 topic 文件的完整镜像；改为一条不失真的关键词级摘要，详细内容只保留在 topic 文件。
- 已有明确后续记录否定的旧事实。
- 项目级路径迁移到 `pending-migration/` 暂存区（安全可逆操作，有备份可回滚）。

**自动≠静默：** 低风险项可由 AI 直接执行，但必须满足两个条件——执行前完成备份，执行后在维护报告中逐条告知用户"改了什么、为什么"。用户要的是更省心，不是被蒙在鼓里。

### 中风险：只审计、建议、等待确认

- 疑似项目级但可能跨项目复用的路径、命令、联系人或工具信息。
- 语义接近（核心信息一致但适用条件/范围不同）但合并可能丢掉适用条件的规则。
- 疑似失效但没有直接证据的信息。
- 用户偏好、技术环境、工作方式等事实性内容。
- 超过时效验证周期但未确认失效的技术参考条目。

### 高风险：绝不自动改

- 用户明确要求长期记住的内容。
- 三条核心工作原则。
- 用户身份、职业、组织或长期关系的实质性修改。
- `MEMORY.md` 的架构、职责与准入规则。

## 执行模式

审计触发时，AI 根据触发来源选择执行模式：

| 模式 | 触发条件 | 低风险处理 | 中高风险处理 |
|---|---|---|---|
| 交互模式 | 用户主动发起审计 | 展示变更计划→确认后执行 | 展示计划→等用户确认 |
| 自动化模式 | 定时任务触发（消息含自动化标记或用户在 prompt 中指定） | 直接执行→报告中逐条告知 | 跳过→报告中标记为遗留项 |

**模式判据：** 尝试识别消息中的自动化标记（如 `<automation_execution>`）。该标记格式未经产品文档正式确认，**无法确定时默认按交互模式处理**。用户也可在 prompt 中显式指定"按自动化模式执行"。

**风险分级补充：** 安全可逆的操作（如项目级路径迁移到 `pending-migration/` 暂存区）应定为低风险，使自动化模式也能直接处理。操作是否可逆（有备份、可回滚）是风险分级的关键判据，而非操作类型本身。

## 标准维护流程

### 1. 建立审计基线（使用脚本）

**使用审计脚本自动完成机械工作，不要手动逐文件读取和计数。**

**产物目录规范：** 审计脚本输出（`audit-baseline.json`）和审计报告都存放在**记忆仓库**下，不放在技能目录。

```bash
# 通过 .cmd 启动器执行（Windows）——不传 --output 时自动输出到记忆仓库下
scripts\run-audit.cmd

# 或直接调用 Python
python scripts/memory_audit.py
```

脚本自动完成：
- 读取所有记忆文件并统计条目数、行数、文件大小、最近修改时间
- 检测同文件内逐字重复
- 检测 profile.md 与 topics 文件的跨文件镜像
- 检测项目级路径违规（路径模式匹配）
- 检查 profile.md 画像摘要的精炼度（条数偏多、单条过长时给出软提示，供人工判断；不设固定条数硬上限）
- 输出结构化 JSON 报告

**AI 读取脚本输出的 JSON 后，进行语义判断：**
- 审计脚本只做机械匹配（精确重复、子串包含、模式匹配），语义等价和语义接近的判定由 AI 完成

**注意：raw/memories.md 不参与审计。** raw 快照不烧 token、不自动注入，审计脚本只统计快照数量用于报告，不做归档判定或清理建议。

**增量审计模式：** 如果 `audit-reports/` 中存在上次审计报告，读取其时间戳，在审计报告中标注哪些文件自上次审计后有变更。对未变更文件复用上次审计的语义判断结论（如有记录）。审计报告需标注"增量审计"或"全量审计"模式。

### 2. 做七项检查

基于审计脚本输出 + AI 语义判断，完成以下检查：

1. **职责检查**：每条是否进入了正确文件。跨维度信息按"主要用途"归类规则判定。
2. **准入检查**：是否混入项目级、一次性或技能产物信息。依据规范第二~三节的入库决策流程判断信息属性。
3. **去重检查**：
   - 同文件逐字重复 → 低风险自动处理
   - 跨文件语义等价（信息点+适用条件一致）→ 低风险自动处理
   - 跨文件语义接近（核心信息一致但适用条件/范围不同）→ 中风险建议合并
4. **精简检查**：`profile.md` 画像是否精炼——条数是否明显偏多、单条是否过长、是否完整镜像 topics。均为软提示，由人工判断精炼空间，不强制删除。

   **精简模板（指导性参考，非硬阈值）：** 按 topics 三个分区（用户偏好/助手反馈/长期参考）组织，每个分区将多条相关条目合并为 1-3 条关键词摘要。摘要保留信息点关键词而非完整句子，多条同主题合并为一条（如"不编程""无CUDA""EDR监控"合并为"环境：Windows开发机，无CUDA、CPU推理、EDR监控"）。单条尽量不超 80 字符。总条数建议目标 20-30 条（指导值，审计脚本仍按 40 条触发软提示）。
5. **失效检查**：是否存在规范已点名清理、明确被纠正或事实失效的内容。
6. **时效检查**：`references.md` 中的技术参考条目是否超过验证周期（软件兼容性 6 个月、CLI 命令/路径/团队关系 12 个月）。超期的在报告中提示"建议验证是否仍然有效"。
7. **迁移检查**：检测到的项目级信息，是否有对应的项目工作区可迁移。无对应工作区的，建议移入 `pending-migration/` 暂存区。

### 3. 先展示变更计划

在任何写入前，输出表格：

| 风险 | 文件与条目 | 拟议动作 | 依据 | 是否立即执行 |
|---|---|---|---|---|
| 低 | … | 删除/合并/精简 | 规范章节或脚本检测证据 | 是 |
| 中 | … | 建议删除/迁移/改写/合并 | 判断理由 | 否，等确认 |
| 高 | … | 仅提示 | 风险原因 | 否 |

**完成条件定义：** 变更计划表格输出完毕，且所有低风险变更已执行完毕、所有中高风险项已给出建议并提交用户确认（无论用户是否已确认），即视为流程完成。用户未确认的中高风险项作为遗留风险记录在报告中。

### 4. 备份后执行低风险变更

如果有低风险变更：

```bash
# 先备份
scripts\run-backup.cmd

# 备份成功后再执行修改
```

备份脚本自动：
1. 在 `backups/YYYY-MM-DD_HH-mm-ss/` 创建备份目录
2. 完整复制所有记忆文件到该目录
3. 逐文件验证备份大小一致性
4. 写入 `_backup_meta.json` 元信息文件

备份验证通过后，执行最小化修改。不得顺手重写无关内容。修改完成后重新读取改动文件，确认目标条目已处理、Markdown 结构未损坏、无意外删除。

### 5. 输出维护报告

在 `audit-reports/YYYY-MM-DD_HH-mm-ss.md` 写入审计报告，并同步展示给用户。报告固定包含：

1. **仓库健康度**：文件数、条目数、重复项、疑似项目项、待确认项、超期技术参考数、raw 快照数（仅统计，不处理）。标注"增量审计"或"全量审计"。
2. **已自动处理**：文件、修改前后摘要、规范依据、备份位置。
3. **待用户确认**：按中风险/高风险分组，给出推荐动作及不处理的影响。
4. **待迁移项**：项目级信息及建议迁移目标工作区或暂存区。
5. **保留理由**：说明未处理的关键项为何保留。
6. **遗留风险**：用户未确认的中高风险项清单。
7. **下次建议**：每月一次；大项目结束后额外运行；无需每次会话都运行。

## 项目级信息迁移

当检测到项目级信息在全局记忆中时：

1. 检查当前是否有对应的项目工作区可用
2. **有对应工作区**：建议迁移到该工作区的 `.agent/memory/`，等待用户确认后执行
3. **无对应工作区**：建议移入 `memory/pending-migration/` 暂存区，在暂存文件中标注来源和所属项目名。暂存区文件不参与桌面端记忆注入
4. **暂存区清理**：下次审计时检查暂存区，如果对应项目工作区已创建，提示用户迁移

## 变更与回滚

用户要求"回滚上一次记忆整理"时：

```bash
# 列出可用备份
scripts\run-restore.cmd --list

# 预览恢复内容（不实际执行）
scripts\run-restore.cmd --backup-dir "backups\2026-07-31_16-30-00" --dry-run

# 确认后执行
scripts\run-restore.cmd --backup-dir "backups\2026-07-31_16-30-00"
```

恢复时用备份文件直接替换对应目标文件；不做智能合并。恢复完成后重新读取并报告结果。

## 并发控制

技能启动时先检查 `audit-reports/` 中是否有"进行中"状态的审计报告（报告头部标记 `status: in_progress`）。如果存在，提示用户"上次审计未完成"，询问是否继续或作废重来。审计完成时将报告状态更新为 `status: completed`。

## 边界

- 不修改云端自动注入记忆和 `<!-- local-agent-company-identity:start/end -->` 身份块。
- 不把项目日志或临时工作成果写回桌面端全局仓库。
- 不因"看起来更干净"删 `raw/memories.md` 中的快照（raw 不参与审计，只在用户主动要求时处理）。
- 不把历史证据、推断、事实混为一谈。
- 不把低风险"自动修剪"扩大为自动改写用户画像或行为规则。
- 不在未经备份的情况下执行任何写入操作。
