# 用户研究笔录校准

**版本：v2.5.2**

## 术语

- **使用者**：调用本 Skill 的研究人员或项目成员。
- **用户**：深访、座谈会、跟访或体验研究中的受访对象。
- **跟访人**：在访谈中旁听、提问、反馈或现场协助的业务方、项目成员或其他非主持研究人员。角色一经确认，在正式访谈和用户离场后的内部复盘中均保持同一称谓。正式笔录中不显示真实姓名：单人显示“跟访人”，多人按首次有效发言顺序显示“跟访人A”“跟访人B”等。
- **督导**：负责研究质量或现场组织的人员，通常不参与录音中的正式对话。
- **现场编号**：座谈会由主持人、座位牌、白板或现场称呼使用的编号，例如“1号”“用户5”。该编号只表示当场参与者顺序，不等同于用户执行表、招募表或其他资料中的样本编号。
- **身份置信度**：对“原始说话人—规范身份”对应关系的判断等级，分为高、中、低；它决定正式笔录显示姓名、现场编号还是原始说话人标签。

## 目标

将 AI 转录稿整理为可直接交付、阅读和归档的 Markdown 用户笔录。笔录忠实保留用户表达、访谈顺序、测试过程和事实边界，同时具备清晰的研究档案、内容索引和角色标识。

## 适用材料

| 材料    | 用途               | 核对重点                    |
| ----- | ---------------- | ----------------------- |
| 转录稿   | 形成笔录正文           | 时间戳、原始说话人、发言顺序、测试过程     |
| 用户信息表 | 核对受访者信息和项目关键标签   | 匿名编号、人口信息、招募标签、设备与行为背景  |
| 访谈脚本  | 建立访谈模块、测试阶段和内容索引 | 研究项目、研究主题、模块名称、刺激物与任务流程 |

收到任务后，先列出已收到材料和待补充材料。材料未齐时，仅说明已收到材料、缺失材料及其用途，并请求补充；不得提前进行全稿扫描、角色映射、关键校准项或待确认事项梳理。使用者补充材料，或明确说明某项材料不存在、无法提供或要求按现有材料继续后，再进入全稿校准。

## 校准流程

### 阶段一：材料核对

1. 核对三类材料的文件或版本信息。
2. 核对研究项目、场次编号、受访者编号、访谈日期和访谈形式。
3. 存在缺失材料时，只说明核对结果和待补充材料；等待使用者补充，或取得其按现有材料继续的明确指示后再进入下一阶段。
4. 三类材料齐备，或使用者已明确材料缺失边界后，进入全稿扫描。

### 阶段二：全稿扫描与校准确认

全稿扫描聚焦以下内容：

- 原始说话人、现场编号、姓名、主持人、跟访人、督导与内部复盘参与人的对应关系及身份置信度；
- 同一人被拆为多个原始说话人、多个原始说话人混入同一身份、说话人串线或连续发言误分的迹象；
- 人名、品牌、产品、项目术语、数字、价格、评分、型号和测试材料名称；
- 测试阶段、展示内容、用户评价、追问和评价变化；
- 用户离场后的研究团队讨论起点，以及用户发言、研究人员发言、现场操作和内部复盘的内容边界；
- 需要统一的术语与需要保留的原始表达。

扫描结束后，先向使用者展示校准确认单。确认单采用以下结构：

```markdown
## 校准确认单

### 材料核对

| 材料 | 文件或版本 | 核对结果 |
|---|---|---|
| 转录稿 | [文件名] | 已核对 |
| 用户信息表 | [文件名] | 已核对 |
| 访谈脚本 | [文件名] | 已核对 |

### 角色映射

| 原始说话人 | 时间范围 | 建议角色 | 正式显示身份 | 现场编号 | 身份置信度 | 依据与影响范围 |
|---|---|---|---|---|---|---|
| [说话人标签] | [完整时段/拆分时段] | [主持人/用户/跟访人/其他角色] | [姓名/称谓/用户N/跟访人A/原始标签] | [1号/用户5/无] | [高/中/低] | [自我介绍、问答关系、时间戳、现场编号或资料核验；说明拆分、合并或未确认影响范围] |

> 用户执行表中的样本编号仅用于补充档案或交叉核验。除非使用者明确提供“现场编号—执行表编号”映射，否则不得将两类编号直接互换。

### 关键校准项

| 类别 | 原始记录 | 建议写法 | 依据 | 需确认事项 |
|---|---|---|---|---|
| [身份/术语/数字/评分/刺激物] | [原始记录] | [建议写法] | [材料位置或时间戳] | [确认内容] |

请确认以上角色映射与关键校准项，或直接补充修改意见。收到确认后生成正式笔录。
```

使用者明确确认、修改或补充后，将确认结果写入正式笔录。确认信息与来源位置保留在内部工作记录，不写入正式笔录。

## 信息判断

### 信息优先级

1. 当前任务中使用者明确确认、补充或选择的信息；
2. 转录稿中可由时间戳定位、前后相互印证的现场事实、称呼、行为和表达意图；
3. 用户信息表和访谈脚本中与转录不冲突的信息，用于补充研究档案、背景信息、模块和刺激物；
4. 保持文档结构一致的格式处理。

多份材料冲突时，优先保留转录中可定位且能反映现场真实发生情况的信息；其他资料不覆盖现场编号、现场称呼、说话人身份、实际日期、实际流程或用户原话。仅当转录证据不足，或使用者明确确认其他材料应作为更正依据时，才采用其他材料。

### 角色、编号与关键事实

- 规范身份以转录稿中的自我介绍、问答关系、连续发言特征和现场编号为主证据；用户执行表用于补充人口信息与交叉核验，不得单独作为座谈会现场编号或发言人身份的映射依据。转录中的现场编号、称呼和互动关系证据充分时，直接采用，不把“是否保留现场编号”列为待确认事项。
- 座谈会身份按以下降级顺序显示：经确认的具体姓名 > 经确认的姓氏称谓（如张女士） > 经确认的现场编号（如用户5） > 原始说话人标签。深访优先显示经确认的受访者称谓；无法确认时使用原始说话人标签。
- 高置信度可直接统一姓名或称谓；中置信度仅使用已确认现场编号，不恢复姓名；低置信度保留原始说话人标签或“用户”，并在确认单中列出待核验项。
- **档案字段证据链**：研究档案和参与者背景字段按以下顺序补全：使用者明确确认的信息 > 已核对材料中的明确字段 > 转录中由已确认受访者直接陈述、可由时间戳定位且与现有材料不冲突的事实 > 输入完整且计算无歧义的推导结果。可据此补全年龄或年龄段、性别、职业、学历、地区、生活阶段、设备、使用产品或服务、使用频率或时长、消费或订单情况等事实字段。仅用于判断的原始依据不写入正式笔录。
- 性别可由已核对材料明确提供，或由使用者确认且具有明确性别指向的正式显示身份（如“姜先生”“李女士”）补全；中性称谓、姓名字形、声音、职业或单次转录称呼均不能单独推断性别。年龄仅在材料明确提供、受访者直接陈述，或由完整出生日期和明确访谈日期无歧义计算时补全；受访者仅表述“20多岁”等宽泛年龄段时，可按原意展示为年龄段，但不得伪造具体年龄。若同一档案字段的不同来源存在互斥记录，或无法判断其是否属于不同维度（如职业类别与所属行业），在校准确认单列为背景信息待确认项；未经使用者确认，不静默覆盖或合并。称谓、资料或身份存在冲突或不确定时，不展示受影响字段。无法可靠确认的字段直接省略，不得以“未提供”“未知”或推测性内容补位。档案字段不作为姓名、称谓或身份映射的独立证据，也不得提高身份置信度。
- 同音或近音姓氏仅在录音复听、自我介绍、现场互称、连续问答关系或使用者确认能够相互印证时统一；不得仅按音近程度或执行表姓名自动校正。证据不足时保留原始称呼并在确认单中列为待核验。
- 当出现“称呼与现场编号冲突”“称呼与自我介绍冲突”或“资料表无对应姓名”时，不判断为现场口误或转录错误；只记录为身份未确认，除非重新听录音或使用者确认。
- 原始说话人不强制一对一映射：有充分上下文证据时，可将同一人的多个原始说话人标签合并；发现一个原始说话人混入多人发言时，按可定位时间段拆分。无法可靠拆分时保留原始标签，并标记影响范围。
- 姓名、身份、产品名、品牌名、型号、数字、价格、评分和测试材料名称采用确认后的写法；评分优先忠实保留转录现场记录，除非使用者明确要求以其他表格或材料校准。
- **原始口语保留，已确认的专名校准**：正文逐字保留用户、主持人和跟访人的语气、重复、停顿、程度、否定、犹豫、比较、转折、现场操作及表达意图；已由使用者确认，或由转录与已核对材料相互印证的项目名、品牌名、IP名、产品名、人名、型号、地名和测试材料名，在研究档案、章节标题、内容索引和每一处正文发言中统一为确认写法。专名校准不得改写观点、语气、程度或表达意图。
- 专名证据不足、资料冲突或仅凭同音/近音无法判断时，不擅自替换正文原始表达；在校准确认单列出待核验项。资料之间存在不同记录时，在校准确认单中呈现原始记录、依据和建议写法。
- 经确认仍无法统一的内容保留原始表达或原始说话人标签。

## 笔录校准

### 角色与术语

- 根据自我介绍、问答关系、现场编号、连续发言特征、用户信息表和访谈脚本识别角色。优先识别主持人、用户、跟访人和督导；跟访人以业务方提问、旁听反馈或现场协助为线索，督导在录音中无正式发言时不写入参与者信息。
- 主持人默认显示为“主持人”。存在多位主持人时，按首次有效发言顺序稳定标为“主持人A”“主持人B”等；除非使用者明确要求，正式笔录不显示主持人真实姓名。
- 跟访人是跨全文稳定的规范角色：单名跟访人显示为“跟访人”，多名跟访人按首次有效发言顺序稳定标为“跟访人A”“跟访人B”等；除非使用者明确要求，正式笔录不显示其真实姓名。用户离场后，已确认的跟访人仍沿用同一称谓写入“内部复盘记录”。
- 主持人、用户、跟访人、研究人员、记录员、翻译和产品演示人员均采用跨全文稳定的规范角色，不因用户是否离场或内容进入内部复盘而自动改名。只有同一原始说话人确有可定位证据表明承担不同角色时，才按时间段拆分；证据不足时保留较保守且已成立的角色，例如“跟访人”，而不擅自改为“研究人员”。
- 出现其他角色时，依据其在访谈中的实际职责命名，例如研究人员A、记录员、翻译或产品演示人员。
- 先建立“原始说话人—时间段—规范身份”映射，再整理正文；角色映射默认覆盖整场录音，只有证据充分时才拆分时间段。遇到疑似错分时，使用自我介绍、称呼回应、语气/话题连续性、前后问答关系和时间连续性复核；只在证据充分时合并或拆分发言。
- 建立确认专名表后，统一正文、研究档案、内容索引和标题中的人名、品牌、产品、项目、IP、型号与测试材料名称；不得只统一档案或标题而遗漏正文。无法确认的专名保留原始表达。
- 忠实保留原始口语与现场过程，包括重复、停顿、口头回应、设备或材料操作和现场协调；仅移除纯环境噪音或无可辨识语言内容。
- 合并同一角色的连续短句和明显断行时，不删除或改写否定、犹豫、程度、比较、转折、评价变化及任何会改变表达意图的内容。

### 场景与测试阶段

依据访谈脚本和实际转录内容建立章节。常见场景包括：

- 开场与自我介绍
- 用户画像与相关行为
- 产品或服务体验
- 概念、方案或实物测试
- 价格测试
- 路径与页面操作
- 访谈收尾

每个测试阶段保持“展示内容—用户评价—追问—评价变化”的顺序。用户仍在场时产生的反馈编入对应研究模块；识别到全部用户离场、正式收尾完成或对话转为研究团队讨论后，立即截出后续内容，不再写入正式笔录正文。

## 研究档案与参与者信息

研究档案采用“通用字段 + 项目重点字段 + 参与者信息与观察”的结构。正式笔录只保留一个参与者相关区块，不再重复设置“参与者概况”和“参与者与角色”。

### 通用字段

以下字段按“档案字段证据链”提取和补全。仅展示有可靠依据的字段；资料不足时省略字段，不以占位内容补齐。

| 字段     | 写法              |
| ------ | --------------- |
| 研究项目   | 正式项目名称          |
| 研究主题   | 本场研究主题          |
| 场次编号   | 城市、场次、样本编号等稳定标识 |
| 受访者    | 匿名编号            |
| 访谈形式   | 深访、座谈会、跟访或体验访谈  |
| 访谈日期   | YYYY-MM-DD      |
| 时长     | 录制时长或转录覆盖时长     |
| 性别     | 仅在档案字段证据链支持时标注  |
| 年龄或年龄段 | 仅在档案字段证据链支持时标注  |
| 职业     | 仅在档案字段证据链支持时标注  |
| 学历     | 仅在档案字段证据链支持时标注  |

### 项目重点字段

从用户信息表和访谈脚本识别本项目用于分层、招募或分析的关键信息，选择 2–5 项写入研究档案。同一项目的不同场次采用同一组字段和相同写法。

可选字段包括：设备与系统、使用产品或服务、使用频率或时长、消费或订单情况、核心任务、渠道偏好、搜索工具、招募标签、地区与生活阶段。

### 参与者信息与观察

参与者信息与观察服务于后续检索和跨场次理解，仅依据已核对材料和本场明确表达填写。标签描述具体、克制，不使用人格诊断或超出访谈证据的推测。

- **深访、跟访或单一受访者场次**：使用纵向表，将身份、招募信息和人物理解标签合并呈现。
- **座谈会或多受访者场次**：使用交叉表，每行一名用户；前半部分呈现角色与稳定身份，后半部分呈现 0–2 个有时间戳依据的观察标签。资料不足的单元格留空，不以推测补齐。

| 字段或观察维度 | 写法或标签示例                       |
| ------- | ----------------------------- |
| 正式显示身份  | 经确认姓名、姓氏称谓、现场编号或原始标签，按身份置信度降级 |
| 角色与原始标签 | 用户/主持人/研究人员等；必要时保留原始说话人标签     |
| 招募与背景信息 | 年龄、职业、设备、招募标签、地区与生活阶段等已核对信息   |
| 生活状态    | 独处生活、家庭导向、社交活跃、工作节奏快          |
| 行事风格    | 计划周密、随性行动、效率优先、体验投入           |
| 消费原则    | 价格敏感、品质优先、设计驱动、品牌认同、功能优先      |
| 信息与决策方式 | 主动搜索、内容种草、熟人推荐、参数比较、冲动尝新      |
| 价值取向    | 悦己、实用、个性表达、品质信任、节制消费          |

每个观察维度提炼 0–2 个标签，并在单元格中附一句简短事实依据和对应时间戳；材料不足时不展示该维度。

## 标准结构

标题、内容索引和参与者信息跨项目统一使用以下结构。

### 标题与文件名

- 文档标题：`[研究项目] 用户笔录校准版｜[场次编号]｜[受访者]`
- 文件名：`用户笔录校准版_[研究项目]_[场次编号]_[受访者]_vX.Y.md`

同一场次更新时递增版本号。

### 内容索引

内容索引使用“模块—时间范围—内容摘要”三列。模块名称采用访谈脚本中的研究模块；时间范围覆盖完整、连续的正文区间。每一条内容摘要必须脱离正文独立说明该时间段的具体主题，至少包含讨论或测试对象及所讨论的具体事项；存在可确认的核心反馈、决策、问题或评价变化时，一并简要写明。摘要只概述该区间已有事实，不补充正文未表达的结论；不得使用“见正文”“同上”“略”“详见下文”等占位、指代或无法独立理解的表述。

### 离场后内部复盘

识别到用户离场后的研究团队讨论时，交付第二份附属 Markdown 文档，文件名为：`内部复盘记录_[研究项目]_[场次编号]_vX.Y.md`。

附属文档不并入正式笔录，也不使用正式笔录的研究档案、内容索引或参与者信息。仅包含两个部分：

1. `## 内容总结`：按讨论主题提炼已发生的流程问题、素材反馈、待跟进事项或后续调整方向；不将推测写成既定决策。
2. `## 原话记录`：按时间戳、已确认的稳定角色和原始顺序保留离场后的讨论记录；身份无法确认时保留原始说话人标签。

若无法判断用户是否已离场，先在校准确认单中列为边界待确认项，不擅自拆分。

## 交付

始终交付一份 `用户笔录校准版` Markdown 文件。若存在已确认的用户离场后内部复盘，额外交付一份 `内部复盘记录` Markdown 文件。逐字发言忠实保留原始表达；研究档案、参与者信息与观察、内容索引、角色名称和场景标题采用中性、专业、清晰的研究表达。

## 交付校验

- 转录稿、用户信息表、访谈脚本和使用者确认均已具备；
- 标题、文件名、研究档案、内容索引和参与者信息与观察完整且命名一致；
- 内容索引的每一条摘要均包含可独立理解的具体主题，未使用“见正文”“同上”“略”“详见下文”等占位或指代表述；
- 单人场次使用纵向参与者信息表；座谈会使用多人交叉表，不重复设置参与者概况和角色表；
- 档案字段按证据链尽可能完整呈现：使用者确认、已核对材料、可定位的受访者直接陈述或无歧义推导均已纳入；无法可靠确认的字段已省略，未以“未提供”“未知”或推测性内容补位；
- 参与者观察有明确访谈依据与时间戳，且不超出材料事实；
- 每个研究档案字段、术语、数字、评分、价格和测试材料名称均可关联至已核对材料或使用者确认；
- 现场编号与执行资料表编号未被直接互换；存在映射时，有明确使用者确认或可追溯映射依据；
- 身份显示符合置信度降级规则；无法确认的姓名或称呼未被强行恢复；
- 同一人拆分为多个说话人或多人混入同一说话人的疑点已扫描；任何合并或拆分均有可追溯上下文依据；
- 时间戳、角色、发言顺序和测试阶段可追溯；
- 用户观点、主持人、跟访人、现场操作和内部复盘边界清晰；跟访人在用户仍在场时显示为“跟访人/跟访人A、B……”，内部复盘已从正式笔录截出并单独交付；
- 术语、数字、评分、价格和时间采用已确认信息或保留原始表达；
- 已确认专名在研究档案、标题、内容索引和正文中写法一致；正文未残留已确认专名的同音误转、变体或错误转写；
- 专名校准未改变任何发言的观点、语气、程度、否定、犹豫或表达意图；
- 文件可直接用于阅读、归档和后续研究分析。
